# Phase 3 Plan 03-01: Docling Structured Document Extraction & Table Parsing

## Goal

Integrate Docling (`docling_reader.py`) to extract reading order, heading hierarchy, section structures, and markdown tables from digital PDFs, generating canonical `Chunk` and `Page` models with `extraction="docling"` and fallback to `PdfReader` (pypdf), fully tested offline.

## Requirements covered

- **INGEST-03**: System processes documents using Docling to extract reading order, headings, section hierarchy, tables, and figure references.

## Depends-on

- Phase 1 canonical models (`models.py`) and storage (`doc_store.py`).
- Phase 0 test harness (`tests/conftest.py`, `tests/data/corpus/`).

## Tracer Slice

Construct `DoclingReader` with an in-memory PDF stream → process `dense_table.pdf` → verify table is extracted as a markdown-formatted table block → verify generated `Chunk` objects carry `extraction="docling"` and valid page indices → verify graceful fallback to `PdfReader` when Docling is unavailable.

## Codebase Map Alignment

- **ARCHITECTURE.md**: Implements the structured parsing stage in the ingestion layer alongside `pdf_reader.py`. Maintains strict one-way dependency flow into canonical `models.py`.
- **CONCERNS.md**:
  - Mitigates **"Chunk character offsets never populated"**: Captures character offsets from Docling document items when available.
  - Mitigates **"Partially unpinned runtime dependencies"**: Declares `docling` in dependency specifications.
- **CONVENTIONS.md**:
  - Implements flat module structure at repository root (`docling_reader.py`).
  - Uses optional-import pattern (`try: import docling ... except ImportError: ...`) so missing native dependencies degrade to `PdfReader` rather than crashing the application.
  - Preserves Google-style docstrings and Pydantic v2 validation.
- **INTEGRATIONS.md**: Ingestion operates 100% locally on CPU (`do_ocr=False` in Docling pipeline) without network egress.
- **STACK.md**: Adds `docling` to `requirements.txt` with CPU pipeline configuration.
- **STRUCTURE.md**: Places new reader in repo root (`docling_reader.py`) and tests in `tests/test_docling_reader.py`.
- **TESTING.md**: Verifies extraction offline using synthetic corpus files (`dense_table.pdf`, `clean_digital.pdf`) with mock fallback seams.

## Design Locks

- **D1 Optional-dependency pattern:** If `docling` is not installed, `DoclingReader` logs a diagnostic warning and delegates to `PdfReader` (pypdf), ensuring zero breaking regressions.
- **D2 CPU-only pipeline:** Configure `PdfPipelineOptions(do_ocr=False, do_table_structure=True)` to prevent VRAM consumption and avoid duplicate OCR execution.
- **D3 In-memory streaming:** Pass `io.BytesIO` streams via Docling's `DocumentStream` to avoid writing temporary files to disk.
- **D4 Markdown table representation:** Export extracted table structures as Markdown tables embedded in `Chunk.content` with `extraction="docling"`.
- **D5 Cache version bump:** Update `CONFIG_VERSION` in `models.py` from `"chunker-1000-200-pypdf"` to `"docling-1000-200-v1"` to ensure stale pypdf-only caches are invalidated.
