# Phase 2 Plan 02-01: BaseModelProvider Interface & LlamaCppProvider Client

## Goal

Define a unified, extensible `BaseModelProvider` interface (`model_provider.py`) with capability introspection and health checking, and implement `LlamaCppProvider` (`llama_cpp_provider.py`) as a robust HTTP client communicating with `llama-server` over local REST endpoints, fully tested 100% offline via mock transports.

## Requirements covered

- **INF-01**: System provides a unified `BaseModelProvider` interface supporting text generation, token streaming, image analysis, and capability inspection.
- **INF-02**: System implements a local `LlamaCppProvider` communicating with `llama-server` running a quantized 2B VLM (Qwen3-VL 2B GGUF Q4_K_M) with health checks and bounded context (4K-8K tokens) (client & communication half).
- **INF-03**: System operates 100% offline without outbound network calls during local mode.

## Depends-on

- Phase 1 canonical models and storage foundation (`models.py`, `doc_store.py`).
- Phase 0 test harness (`tests/conftest.py`, `pyproject.toml`).

## Tracer Slice

Construct a `LlamaCppProvider` configured for `http://127.0.0.1:8080` with an `httpx.MockTransport` returning mock SSE stream chunks → verify token generator yields exact text chunks → verify health check returns `HealthStatus(status="healthy")`. This tracer path proves provider creation, capability introspection, streaming parsing, and offline testability before expanding into full error boundaries.

## Codebase Map Alignment

- **ARCHITECTURE.md**: Conforms to the layered service orchestration design. Replaces the direct Groq coupling in the inference layer with a decoupled provider adapter pattern.
- **CONCERNS.md**:
  - Mitigates **Risk #1 (Unhandled Groq startup crash)**: `BaseModelProvider` introduces structured `check_health()` and typed `HealthStatus` preventing unhandled exceptions when inference backends are unreachable.
  - Mitigates **Risk #2 (Prompt injection & overflow)**: Provider accepts separate `system_prompt`, `prompt`, and `history` lists, formatting them cleanly into message roles rather than unstructured string concatenation.
- **CONVENTIONS.md**:
  - Implements flat module structure at repository root (`model_provider.py`, `llama_cpp_provider.py`).
  - Uses Pydantic v2 schemas (`ProviderCapabilities`, `HealthStatus`) with `frozen=True` and `extra="forbid"`.
  - Uses standard Python type hints with builtin generics (`str | None`, `list[dict[str, str]]`, `Generator[str, None, None]`).
  - Unit tests placed in `tests/test_model_provider.py` and `tests/test_llama_cpp_provider.py`.
- **INTEGRATIONS.md**: Implements local-first REST communication targeting `llama-server` without external network access.
- **STACK.md**: Adds `httpx>=0.28.0` to `requirements.txt` as specified in STACK.md recommendations.
- **STRUCTURE.md**: Places new core logic files in the root modular monolith and tests in `tests/`.
- **TESTING.md**: Ensures 100% offline unit tests using `httpx.MockTransport` without requiring GPU or live servers in CI.

## Design Locks

- **D1 Pydantic v2 schemas:** `ProviderCapabilities` and `HealthStatus` defined in `model_provider.py` using `BaseModel`, `ConfigDict(frozen=True, extra="forbid")`, and `Field`.
- **D2 Pure abstract interface:** `BaseModelProvider` inherits from `abc.ABC` with abstract methods: `generate_text`, `stream_text`, `analyze_image`, `check_health`, and `get_capabilities`.
- **D3 Synchronous HTTP via `httpx`:** Use `httpx.Client` with explicit timeouts (2.0s connect for health checks, 60.0s read for generation).
- **D4 SSE streaming protocol:** Implement SSE parser that handles `data: {"choices": [{"delta": {"content": "..."}}]}` and terminates cleanly on `data: [DONE]`.
- **D5 Actionable setup guidance on failure:** When `llama-server` is unreachable, `check_health()` returns `status="unreachable"` with a clear diagnostic message including the exact command line to start `llama-server`.
- **D6 Multimodal format:** `analyze_image` formats images as base64 data URLs in OpenAI-compatible vision payload structure.

### Task 4 — Implement `llama_cpp_provider.py`
- **Files to touch:** `llama_cpp_provider.py` (new, repo root)
- **What to do:**
  - Implement `LlamaCppProvider(BaseModelProvider)`:
    - `__init__(base_url="http://127.0.0.1:8080", model_name="qwen3-vl-2b", context_window=4096, transport=None)`
    - `check_health() -> HealthStatus`: queries `base_url + "/health"`. Handles 200 (healthy), 503 (loading), connection errors (unreachable with command guide).
    - `get_capabilities() -> ProviderCapabilities`: returns local capabilities (`is_local=True`, `supports_vision=True`, `context_window=4096`).
    - `generate_text(...) -> str`: sends POST `/v1/chat/completions` with `stream=False`.
    - `stream_text(...) -> Generator[str, None, None]`: sends POST `/v1/chat/completions` with `stream=True`, parses SSE chunks line-by-line, yields `delta.content`.
    - `analyze_image(...) -> str`: converts `image_bytes` to base64, formats OpenAI vision message, queries completions endpoint.
- **Test command:** `pytest tests/test_llama_cpp_provider.py -v` (Task 5)
- **Commit message:** `feat(02): implement LlamaCppProvider HTTP client with streaming and health checks`
