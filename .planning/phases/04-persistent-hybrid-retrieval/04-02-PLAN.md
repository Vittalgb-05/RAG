# Phase 4 Plan 04-02: Hybrid Retrieval with BM25 FTS, Reciprocal Rank Fusion, and Shared RetrievalResult Contract

## Goal

Implement hybrid search combining dense semantic vector search and BM25 full-text keyword search via Reciprocal Rank Fusion (RRF), delivering sub-second candidate retrieval and an immutable, shared `RetrievalResult` contract consumed identically by generation prompts and UI citation rendering (RETR-03, RETR-04).

## Requirements covered

- **RETR-03**: System executes hybrid retrieval combining semantic vector search and full-text keyword search (BM25/FTS) with Reciprocal Rank Fusion (RRF).
- **RETR-04**: System provides a single shared `RetrievalResult` context consumed identically by both generation prompts and citation display components.

## Depends-on

- Plan 04-01 (`hybrid_retriever.py`, persistent LanceDB storage, CPU-pinned embeddings).
- Phase 1 canonical models (`models.py`, `BBox`).
- Phase 2 prompt budgeting (`prompt_budget.py`).

## Tracer Slice

Index diverse chunks containing both semantic concepts and exact keywords (e.g. acronyms like "RTX 3050" or table IDs) → query with exact keywords and semantic variants → execute `HybridRetriever.search_hybrid(query, k=5)` → verify RRF score calculation and rank ordering → verify `RetrievalResult` output is immutable and contains `EvidenceSnippet` records with full provenance → verify generation prompt formatting with explicit numbered references (`[E1]`, `[E2]`) matches UI citation data identically.

## Codebase Map Alignment

- **ARCHITECTURE.md**: Unifies retrieval across query and UI paths by replacing separate search calls with a single `RetrievalResult` contract. Feeds `assemble_grounded_messages` in `local_llm.py` and source display chips in `main.py`.
- **CONCERNS.md**:
  - Mitigates **"Prompt injection from document text"**: Uses standardized numbered evidence blocks (`[E1]`, `[E2]`) with XML boundary sanitization.
  - Mitigates **"Chunk character offsets never populated"**: Preserves and passes `char_start`/`char_end` throughout `EvidenceSnippet` for future granular citation highlighting.
  - Mitigates **"Stale mock_groq_client fixture"**: Ensures new tests rely on independent, modern fixtures in `test_hybrid_retriever.py`.
- **CONVENTIONS.md**:
  - Strict Pydantic v2 idioms: `ConfigDict(frozen=True, extra="forbid")` for `EvidenceSnippet` and `RetrievalResult`.
  - Implements standalone RRF fusion function with configurable smoothing ($k=60$).
  - Full-text search fallback in pure Python ensures 100% offline testability.
- **INTEGRATIONS.md**: Hybrid search runs 100% locally on CPU without external service dependencies.
- **STACK.md**: Leverages LanceDB FTS index and stdlib algorithms.
- **STRUCTURE.md**: Canonical schemas added to `models.py`, retrieval logic in `hybrid_retriever.py`, and test suite in `tests/test_hybrid_retriever.py`.
- **TESTING.md**: Tests assert RRF scoring math, keyword vs semantic matching advantages, schema immutability, and zero regressions across all 120 existing tests.

## Design Locks

- **D1 Reciprocal Rank Fusion formula:** Use standard RRF formula $RRF(d) = \sum_{m \in \{\text{dense}, \text{fts}\}} \frac{1}{k_{rrf} + rank_m(d)}$ with default $k_{rrf} = 60$. Dense and FTS candidate lists contribute additive reciprocal ranks, guaranteeing stable and scale-invariant rank combination.
- **D2 Immutable shared contract:** `RetrievalResult` and `EvidenceSnippet` must be immutable (`frozen=True`, `extra="forbid"`). The exact same `RetrievalResult` instance retrieved during the query step must be used for both LLM prompt assembly and Streamlit source rendering.
- **D3 Standardized numbered evidence blocks:** `RetrievalResult.formatted_evidence()` produces structured blocks formatted as `[E{rank}] ({filename}, p. {page}):\n{content}`, matching the grounding requirements for Phase 5 (QA-02, UI-03).
- **D4 Offline BM25 fallback:** If LanceDB native Tantivy FTS is unavailable or fails to build an index, `HybridRetriever` provides a pure-Python BM25 keyword search fallback, guaranteeing that hybrid retrieval and tests function deterministically on all platforms.
- **D5 Sub-second retrieval budget:** Candidate limit $k$ defaults to 5–10, with hybrid fusion completing well under 1 second on local CPU.

## Tasks

### Task 1 — Add `EvidenceSnippet` and `RetrievalResult` schemas to `models.py`
- **Files to touch:** `models.py`
- **What to do:**
  - Define `EvidenceSnippet(BaseModel)`:
    - `model_config = ConfigDict(frozen=True, extra="forbid")`
    - Fields: `content: str`, `doc_id: str`, `filename: str`, `page: int`, `chunk_id: str`, `score: float`, `rank: int`, `dense_rank: int | None = None`, `fts_rank: int | None = None`, `extraction: str = "docling"`, `char_start: int | None = None`, `char_end: int | None = None`, `bbox: BBox | None = None`.
  - Define `RetrievalResult(BaseModel)`:
    - `model_config = ConfigDict(frozen=True, extra="forbid")`
    - Fields: `query: str`, `snippets: list[EvidenceSnippet]`, `total_candidates: int`, `search_mode: Literal["hybrid", "dense", "fts", "fallback"]`.
    - Method `formatted_evidence(self) -> str`: Formats snippets into numbered blocks (`[E1] (filename, p. 1):\n{content}\n\n---...`).
    - Method `source_labels(self) -> list[str]`: Returns distinct source references (e.g. `["filename.pdf (p. 1)", ...]`).
- **Test command:** `pytest tests/test_models.py -k retrieval -v`
- **Commit message:** `feat(04): define canonical EvidenceSnippet and RetrievalResult schemas`
