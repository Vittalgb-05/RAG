# Phase 6 Plan 06-02: Multi-Tier Cache Invalidation, Memory Bounds & UI Telemetry

## Goal

Resolve the dual-index RAM duplication debt from `CONCERNS.md` by establishing `HybridRetriever` as the sole persistent index in session state, enforce session memory bounds (limiting chat history to 50 turns to prevent browser RAM bloat), implement comprehensive multi-tier cache invalidation, and embed a live Resource Telemetry widget (VRAM meter, RAM footprint, cache hit status) into the Streamlit sidebar (QUAL-01).

## Requirements covered

- **QUAL-01**: System guarantees memory safety on 4 GB VRAM (RTX 3050 Laptop) by enforcing max one active LLM on GPU and cold/warm memory benchmarks.

## Depends-on

- Phase 6 Plan 06-01 (`resource_telemetry.py`, `InferenceGate`, `profile_resources.py`).
- Phase 4 persistent hybrid retrieval (`hybrid_retriever.py`, `local_embedding.py`).
- Phase 5 grounded summarization and QA (`main.py`, `doc_store.py`).

## Tracer Slice

Upload document corpus → `main.py` indexes directly into `HybridRetriever` without creating duplicate in-memory `VectorIndex` structures, saving process RAM → Streamlit sidebar displays live GPU VRAM meter (Used / Total MB) and process RSS → execute multiple chat queries → chat history automatically bounds at 50 turns → trigger "Clear All" → verifies session keys, summary caches, and retriever handles are purged cleanly without leaking memory.

## Codebase Map Alignment

- **ARCHITECTURE.md**: Streamlines presentation and retrieval layers: demotes `LocalEmbedding` to CPU embedding generator, leaving `HybridRetriever` as the single authoritative index in session state.
- **CONCERNS.md**:
  - Directly resolves **"Dual-index write path"**: Eliminates writing to both `LocalEmbedding` and `HybridRetriever` on upload and dedup-restore.
  - Directly resolves **"Clear All resets session but not persistent stores"**: Clarifies session reset vs. storage cleanup and provides explicit purge hooks.
- **CONVENTIONS.md**:
  - Adheres to Streamlit reactive state conventions in `main.py`.
  - Maintains `MAX_CHAT_TURNS = 50` constant at module level.
  - Pydantic v2 validation contracts preserved.
- **INTEGRATIONS.md**: Telemetry safely renders GPU VRAM status when NVIDIA hardware is present and gracefully degrades to RAM-only or offline status in CI/headless environments.
- **STACK.md**: Leverages existing Streamlit UI primitives (`st.sidebar`, `st.metric`, `st.progress`) and `resource_telemetry.py`.
- **STRUCTURE.md**: Touches `main.py`, `hybrid_retriever.py`, `doc_store.py`, and adds `tests/test_cache_invalidation.py`.
- **TESTING.md**: Tests multi-tier cache invalidation, chat history truncation, and UI telemetry rendering with 100% offline unit tests.

## Design Locks

- **D1 Single Authoritative Index in Session State:**
  - `st.session_state.hybrid_retriever` is the sole retrieval index stored in session state.
  - `st.session_state.local_embedding` is retained strictly as the CPU embedding provider (`_embed_one` / batch encoding), without allocating duplicate in-memory vectors in `VectorIndex`.
  - Ingestion and dedup-restore paths write to `hybrid_retriever` only.
- **D2 Chat History Bounding:**
  - Enforce `MAX_CHAT_TURNS = 50`.
  - When `len(st.session_state.chat_history) > MAX_CHAT_TURNS`, the oldest assistant/user turns are pruned to protect browser memory and state serialization.
- **D3 Sidebar Telemetry Widget:**
  - Renders inside `st.sidebar`:
    - Hardware indicator: VRAM gauge showing `used_mb / total_mb` with color-coded alerts (green `< 3,500 MB`, amber `3,500–3,800 MB`, red `> 3,800 MB`).
    - Process memory: Process RSS footprint in MB.
    - Cache status: Count of indexed documents and cached summaries in SQLite.
