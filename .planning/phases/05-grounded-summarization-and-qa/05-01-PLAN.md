# Phase 5 Plan 05-01: Hierarchical Multi-Profile Summarization Service & Persistent Cache

## Goal

Implement the hierarchical multi-profile document summarization service (`summarizer.py`) delivering five distinct analytical profiles (`overview`, `detailed`, `study_notes`, `tables_figures`, `findings`), map-reduce page tracking across reduction stages, and persistent SQLite summary caching by document SHA-256 and profile type (`doc_store.py`, migration v3) for near-instant repeated requests (SUMM-01, SUMM-02, SUMM-03).

## Requirements covered

- **SUMM-01**: User can generate document summaries across five distinct profiles: Overview, Detailed, Study Notes, Tables & Figures, and Findings.
- **SUMM-02**: System executes hierarchical map-reduce summarization for multi-page documents while maintaining source page references across reduction stages.
- **SUMM-03**: System caches generated summaries by document hash and profile type to deliver near-instant repeated requests.

## Depends-on

- Phase 1 canonical models and storage (`models.py`, `doc_store.py`, `DocStore`).
- Phase 2 inference provider abstraction (`model_provider.py`, `BaseModelProvider`, `prompt_budget.py`).
- Phase 3 structured page and visual element extraction (`Page`, `EvidenceElement`).

## Tracer Slice

Ingest a multi-page PDF document → request summary for profile `study_notes` → `Summarizer` evaluates token count → runs sequential map steps across page bundles with explicit page markers (`Page 1: ...`, `Page 2: ...`) → reduces intermediate summaries into a formatted study guide preserving `(p. 1)` and `(p. 2)` citations → persists summary to SQLite `document_summaries` table (`DocStore`) → re-request identical summary profile → verify cache hit returns instantly with zero provider invocations.

## Codebase Map Alignment

- **ARCHITECTURE.md**: Introduces `summarizer.py` within the Inference / Generation layer, delegating to `BaseModelProvider` and persisting to `doc_store.py`. Conforms to sequential execution to protect the 4 GB VRAM budget.
- **CONCERNS.md**:
  - Mitigates **"Prompt injection from document text"**: Sanitizes page inputs using `sanitize_xml_boundary()` in both map and reduce prompt templates.
  - Mitigates **"Dual-index write path / store synchronization"**: Uses document SHA-256 and canonical `doc_id` from `DocStore`, maintaining SQLite as the authoritative store for summary metadata.
  - Mitigates **"Working-directory-relative artifact paths"**: Reuses existing anchored paths in `DocStore`.
- **CONVENTIONS.md**:
  - Flat module at repository root: `summarizer.py`.
  - Pydantic v2 schemas (`SummaryProfile`, `SummaryResult`).
  - Standard `logging.getLogger(__name__)` with zero bare `print()` statements.
  - SQLite schema migration via `SCHEMA_V3_DDL` with `PRAGMA user_version`.
- **INTEGRATIONS.md**: Map-reduce execution is strictly sequential (single active LLM call at a time), guaranteeing zero VRAM blowouts on the RTX 3050 Laptop GPU.
- **STACK.md**: Uses stdlib `sqlite3`, `re`, `json`, and Pydantic v2. Zero new heavy dependencies.
- **STRUCTURE.md**: Places `summarizer.py` in repo root and tests in `tests/test_summarizer.py`.
- **TESTING.md**: Uses mock providers (`MockTextOnlyProvider` / `MockChoice`) to verify all 5 profiles, map-reduce page tracking, and caching with 100% offline unit tests.

## Design Locks

- **D1 Five Canonical Profiles:**
  - `overview`: Executive summary, core thesis, key takeaways (250–400 words).
  - `detailed`: Section-by-section breakdown of background, methods, data, and conclusions (600–1200 words).
  - `study_notes`: Pedagogical outline with key concept definitions, core takeaways, and review questions.
  - `tables_figures`: Structured synthesis of tables, charts, visual elements, and numerical findings.
  - `findings`: Key discoveries, quantitative conclusions, risks, limitations, and recommendations.
- **D2 Sequential Map-Reduce with Page Tracking:**
  - Batching threshold: $\le 2,000$ tokens per page batch based on `estimate_tokens`.
  - Fast path: Documents $\le 2,500$ tokens execute a single-pass summary with page markers.
  - Multi-pass path: Multi-page batches generate intermediate summaries containing explicit page references (`(p. X)`); reduction stage preserves and unifies these references.
  - Strictly sequential execution: Never run parallel map tasks to ensure memory safety on 4 GB VRAM (QUAL-01).
- **D3 Schema V3 Persistence (`document_summaries`):**
  - Table schema: `summary_id` (PK), `doc_id` (FK), `sha256` (indexed), `profile`, `summary_text`, `page_references_json`, `created_at`, `model_version`, with `UNIQUE(sha256, profile)`.
  - Cache check: `DocStore.get_summary(sha256, profile)` executes before any LLM inference. If present, returns `SummaryResult(..., cached=True)`.

### Task 3 — Implement `Summarizer` service in `summarizer.py`
- **Files to touch:** `summarizer.py` (new, repo root)
- **What to do:**
  - Implement `Summarizer`:
    - `__init__(provider: BaseModelProvider, doc_store: DocStore | None = None)`
    - Define prompt templates for the 5 profiles (`overview`, `detailed`, `study_notes`, `tables_figures`, `findings`) both for mapping and final reduction.

      - Executes single-pass or map-reduce based on total tokens.
      - Persists result to `doc_store.save_summary(...)`.
