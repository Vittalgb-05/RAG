# Phase 7 Plan 07-01: LiteLLM Cloud Provider Adapter & Privacy Consent Gate

## Goal

Implement the unified cloud model adapter (`litellm_provider.py`) using LiteLLM supporting Groq, OpenAI, and Anthropic (`INF-04`), enforce strict programmatic privacy consent checks (`user_consented=True`), bound requests with timeouts (30s) and retries (`num_retries=2`), and refactor `AiModel` (`local_llm.py`) to eliminate silent unconsented cloud fallback, resolving the standing technical debt in `CONCERNS.md`.

## Requirements covered

- **INF-04**: System implements an optional `LiteLLMProvider` enabling cloud model routing (Groq, OpenAI, Anthropic) only when explicitly configured and consented to by user.

## Depends-on

- Phase 2 inference pipeline (`local_llm.py`, `model_provider.py`, `groq_provider.py`, `llama_cpp_provider.py`).
- Phase 6 concurrency lock (`InferenceGate` in `local_llm.py`).

## Tracer Slice

Instantiate `LiteLLMProvider` with `user_consented=False` → verify `generate_text`, `stream_text`, and `analyze_image` immediately raise `PermissionError` → supply `user_consented=True` → verify non-streaming and streaming generation succeed using mocked `litellm.completion` → verify capability inspection across Groq, OpenAI, and Anthropic model strings → update `AiModel` so `_detect_provider()` never silently sends data to cloud when local `llama-server` is unreachable.

## Design Locks

- **D1 Strict Consent Invariant:**
  - `LiteLLMProvider` enforces a `user_consented: bool` flag (default: `False`).
  - If `user_consented` is `False`, calls to `generate_text`, `stream_text`, or `analyze_image` immediately raise `PermissionError("Cloud transmission blocked: explicit user consent is required before transmitting document data to cloud providers.")`.
- **D2 Multi-Model Routing:**
  - Configurable model prefixes:
    - Groq: `groq/llama-3.3-70b-versatile` (128K context, fast text)
    - OpenAI: `openai/gpt-4o-mini` (128K context, multimodal vision)
    - Anthropic: `anthropic/claude-3-5-haiku-20241022` (200K context, multimodal vision)
  - API key lookup resolves per provider type (`GROQ_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`).
- **D3 No Silent Cloud Fallback:**
  - When Cloud Mode is disabled (default), `AiModel` operates strictly in local mode. If `llama-server` is unreachable, `AiModel` returns `LlamaCppProvider` in offline diagnostic state rather than silently redirecting document context to external APIs.
- **D4 Bounded Request Lifecycle:**
  - Every LiteLLM call specifies `timeout=30.0` and `num_retries=2`.
  - Provider exceptions are wrapped into informative `RuntimeError` instances.

## Tasks

### Task 1 — Implement `litellm_provider.py`
- **Files to touch:** `litellm_provider.py` (new, repo root)
- **What to do:**
  1. Add optional-dependency import guard for `litellm`.
  2. Implement `LiteLLMProvider(BaseModelProvider)`:
     - `__init__(model_name, api_key=None, user_consented=False, timeout=30.0, num_retries=2)`
     - `set_consent(consented: bool) -> None`
     - `check_health() -> HealthStatus`: inspects API key presence and library availability without performing billable network inference.
     - `get_capabilities() -> ProviderCapabilities`: maps model name to context window and vision support.
     - `generate_text(...) -> str`: guards consent, clamps temperature, calls `litellm.completion()`, extracts response text.
     - `stream_text(...) -> Generator[str, None, None]`: guards consent, clamps temperature, calls `litellm.completion(stream=True)`, yields chunks.
     - `analyze_image(...) -> str`: guards consent, validates vision support, encodes image to base64 data URI, calls `litellm.completion()`.
     - `close() -> None`: cleanup lifecycle.

### Task 2 — Update `AiModel` in `local_llm.py`
- **Files to touch:** `local_llm.py`
- **What to do:**
  1. Refactor `AiModel.__init__` to accept `cloud_mode: bool = False` and `cloud_provider: BaseModelProvider | None = None`.
  2. Modify `_detect_provider()`:
     - If `cloud_mode=True` and `cloud_provider` is provided: use `cloud_provider`.
     - Otherwise: probe `LlamaCppProvider`. If offline, stay on `LlamaCppProvider` (offline diagnostic status). Remove automatic fallback to Groq when cloud mode is disabled.
  3. Provide `set_cloud_mode(enabled: bool, cloud_provider: BaseModelProvider | None = None)` method on `AiModel` to support dynamic toggling.
  4. Ensure `InferenceGate` concurrency lock continues to guard all inference executions.

### Task 3 — Author Unit Tests in `tests/test_litellm_provider.py`
- **Files to touch:** `tests/test_litellm_provider.py` (new)
- **What to do:**
  1. Test consent gate enforcement: unconsented calls raise `PermissionError`.
  2. Test consent grant: `set_consent(True)` allows calls to proceed.
  3. Test `check_health()` with missing vs provided API key, and when `litellm` is missing.
  4. Test `generate_text()` with mocked `litellm.completion`.
  5. Test `stream_text()` with mocked streaming chunks.
  6. Test `analyze_image()` for vision-capable models and graceful error for non-vision models.
  7. Test exception wrapping into `RuntimeError`.
  8. Test `AiModel` privacy isolation: verify local offline status does not silently route to cloud.
