# Phase 1 Plan 01-02: Robust Upload Validation + SHA-256 Dedup + Ingestion Progress UI

## Goal

Close the upload trust gap: every PDF entering the pipeline passes server-side
magic-byte/size/page-cap validation, is identified by content hash (not filename), survives
single-page corruption without aborting the document, and reports staged progress in the
sidebar — so duplicate uploads are skipped, renamed files don't re-index, corrupt files are
rejected with actionable messages, and users always see what stage ingestion is in.

## Requirements covered

- **INGEST-01**: Client + server-side `%PDF` magic-byte validation, size limit checks,
  page count limits on Streamlit upload.
- **INGEST-02**: Integrity check + SHA-256 content hash, duplicate detection, stable
  `doc_id` independent of filename.
- **INGEST-05**: Page-level fault isolation — one bad page never aborts remaining pages.
- **UI-01**: Upload validation status + page-by-page progress indicators in Streamlit.

## Depends-on

- **01-01** (`models.py` with `Document/Page/Chunk/BBox`, `DocStore`, `CONFIG_VERSION`,
  `pdf_reader.py` emitting `Chunk`-validated dicts). This plan imports all of them;
  do not execute before 01-01 Tasks 1–4 are committed.

## Tracer slice (build first)

Minimal end-to-end dedup path before the rest: upload `clean_digital.pdf` bytes twice
under two different filenames → same `doc_id`, second upload hits `DocStore.get_by_sha`
→ sidebar shows `st.info("Already indexed … — skipped.")` with no re-embedding. Task 3's
test (`test_rename_yields_same_doc_id`) + manual double-upload check prove it; Tasks 1–3
land in order, Tasks 4–7 expand.

## Design locks (from RESEARCH.md — follow unless a factual error is found)

- Validation order (cheap → expensive, fail fast): **magic bytes → size cap → page-count
  cap → SHA-256 → pypdf parse**. `MAX_FILE_MB = 50`, `MAX_PAGES = 500` module constants
  in `upload_validation.py` (ASSUMED values locked by RESEARCH §3-R3; expose as constants
  so a later phase can surface them in UI without code-shape change).
- Single `UploadedFile.getvalue()` call per file; reuse the same `bytes` object for
  magic-byte check, size check, 1 MiB-slice streaming SHA-256, and `BytesIO` parsing —
  never call `getvalue()` twice (it copies; R3). Hash slices 1 MiB.
- `doc_id = "doc_" + sha256[:16]`; `chunk_id = "{sha12}_p{page}_{j}"` (sha12 = first 12
  hex chars). `filename` stays a display column only — never part of identity.
- UI extends `main.py:95-161` idioms (`st.status` + `st.write` per stage +
  `.update(state="complete")`); add `st.progress(0..1)` for the page loop inside the
  status block; `st.error` + `continue` per failure (never `st.stop()` in the loop);
  dedup-hit shows `st.info`. `st.set_page_config` stays first; new session keys go in the
  `main.py:44-51` init loop only.

## Task 1 — `upload_validation.py`: magic-byte/size/page-cap checks + streaming SHA-256

- **Files to touch:** `upload_validation.py` (new, repo root).
- **What to do:**
  1. Top-of-file `"""..."""` summary (match `vector_index.py` style) + Google-style
     docstrings. Stdlib imports only (`hashlib`, `io`, `pathlib`) at top; `pypdf` import
     for the page-count probe (third-party block).
  2. Constants `MAX_FILE_MB = 50`, `MAX_PAGES = 500` at module top with comments citing
     R3 rationale (memory flatness) and that values are RESEARCH-locked ASSUMED caps.
  3. `def sha256_bytes(raw: bytes) -> str:` — 1 MiB update slices, returns 64-char hex.
     `def doc_id_for(sha: str) -> str: return "doc_" + sha[:16]`.
     `@dataclass(frozen=True) ValidatedUpload:` fields
     `doc_id, filename, sha256, size_bytes, num_pages`.
  4. `def validate_pdf_bytes(raw: bytes, filename: str) -> ValidatedUpload:` raising
     `ValueError` with user-actionable messages (exact fragments — tests pin them):
     - `raw[:5] != b"%PDF-"` → `"Not a valid PDF: missing %PDF header — {filename}."`
     - `len(raw) > MAX_FILE_MB*1024*1024` → `"File too large ({mb:.1f} MB > 50 MB) — {filename}."`
     - page count via `pypdf.PdfReader(io.BytesIO(raw))` len(pages) `> MAX_PAGES` →
       `"Too many pages ({n} > 500) — {filename}."`; any `Exception` during this probe →
       `"Unreadable PDF ({err}) — {filename}."` (R4 polyglot path: header passes but parse
       fails — still rejected, never crashes).
     - Success returns `ValidatedUpload` with streaming hash + `doc_id_for`.
     Guard-clause style per `vector_index.py` (raise before any allocation beyond slices).
  5. `print(f"[UploadValidation] ...")` lifecycle diagnostics only; no `st.*` here.
- **Test command:** `pytest tests/test_upload_validation.py -v` (Task 2; red until then)
- **Commit message:** `feat:01-02: add pdf upload validation and sha256`

## Task 3 — `pdf_reader.py`: page-level fault isolation + hash-based chunk IDs (INGEST-05)

- **Files to touch:** `pdf_reader.py` (edit).
- **What to do:**
  1. `extract_text(self, doc_id: str | None = None, sha12: str | None = None)`: wrap the
     per-page `page.extract_text()` + split block in `try/except Exception` → on failure
     record `Page(doc_id=..., page_num=..., status="failed", error=str(e))` in a new
     `self.page_records: list[Page]` (import `Page`/`Chunk` top-level first-party block)
     and `continue` — remaining pages still process (INGEST-05). Empty-text pages record
     `Page(status="empty")` and are skipped for chunking (preserves scanned-zero-chunk
     behavior pinned by existing scanned test). Successful pages record
     `Page(status="ok", char_count=..., num_chunks=...)`.
  2. Chunk-ID migration: `chunk_id = f"{sha12 or self.filename}_p{page_num}_{j}"` —
     when the caller (new `main.py`, Task 4) passes `sha12`, IDs are rename-stable; when
     `None` (legacy/headless callers incl. `local_llm.py:42-43` fallback + existing tests),
     behavior is byte-identical to today (backward compat, no silent orphaning).
     Add `get_page_records(self) -> list[Page]` accessor returning `self.page_records`
     (empty list if `extract_text` never ran — mirror `get_paragraphs` lazy shape).
  3. Keep `'''...'''` docstring flavour; keep bottom commented example (API extended with
     defaulted params — existing call sites unaffected, example still valid).
  4. Do NOT change `chunk_size=1000/chunk_overlap=200` (they are baked into
     `CONFIG_VERSION` from 01-01).
