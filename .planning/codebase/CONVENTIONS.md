# Coding Conventions

**Analysis Date:** 2026-10-11

## Naming Patterns

**Files:**
- Flat `snake_case.py` modules at repo root, one class (or one concern) per file: `main.py` (Streamlit entry point), `local_llm.py`, `local_embedding.py`, `vector_index.py`, `pdf_reader.py`, `models.py` (Pydantic schemas), `doc_store.py` (SQLite store), `upload_validation.py` (upload guards + hashing).
- Test files live under `tests/` as `test_<module>.py`: `tests/test_vector_index.py`, `tests/test_pdf_reader.py`, `tests/test_local_embedding.py`, `tests/test_local_llm.py`, `tests/test_models.py`, `tests/test_doc_store.py`, `tests/test_upload_validation.py`. Shared fixtures in `tests/conftest.py`; package marker `tests/__init__.py` (single docstring).
- Utility scripts live under `scripts/`: `scripts/benchmark_baseline.py`. Synthetic corpus generator at `tests/data/corpus/generate_corpus.py`; generated corpus PDFs are build artifacts regenerated by CI, not hand-written fixtures.
- Test-only dependencies live in `requirements-test.txt` (`pytest`, `reportlab`, `ruff`, `psutil`); runtime pins stay in `requirements.txt` (now includes `numpy>=1.26.0,<3.0.0` and `pydantic==2.11.9`).
- No packages, no barrel files. Imports are direct module imports (e.g. `from local_llm import AiModel` in `main.py:25`, `from doc_store import DocStore` in `main.py:23`, `from models import BBox, Chunk, Document, Page` in `doc_store.py:12`).

**Classes:**
- `PascalCase`, one public class per module: `AiModel` (`local_llm.py`), `LocalEmbedding` (`local_embedding.py`), `VectorIndex` (`vector_index.py:15`), `PdfReader` (`pdf_reader.py:10`), `DocStore` (`doc_store.py:59`).
- Pydantic models in `models.py` are `PascalCase`: `BBox` (`models.py:29`), `Chunk` (`models.py:44`), `Page` (`models.py:65`), `EvidenceElement` (`models.py:80`), `Document` (`models.py:96`).
- `ValidatedUpload` is a frozen dataclass, not a Pydantic model (`upload_validation.py:48-58`) — it is a throwaway validation result, never persisted.
- Test-only doubles use `Mock`-prefixed class names defined inside fixtures, never at module scope: `MockDelta` / `MockChoice` / `MockChunk` inside `mock_groq_client` (`tests/conftest.py:26-36`); `StubReader` defined inside `test_over_page_rejected` (`tests/test_upload_validation.py:67-69`).

**Functions / methods:**
- `snake_case` throughout. New Phase 1 examples: `cache_dir_for` (`models.py:15`), `upsert_document` / `get_document` / `get_by_sha` / `list_documents` / `record_page` / `record_chunks` / `get_chunks_for_doc` (`doc_store.py:108,143,163,183,195,228,272`), `sha256_bytes` / `doc_id_for` / `validate_pdf_bytes` (`upload_validation.py:18,35,61`), `get_page_records` (`pdf_reader.py:129`), `extract_text(doc_id=None, sha12=None)` (`pdf_reader.py:29`).
- Established examples: `ask_a_question_from_pdf_stream` (`local_llm.py`), `build_index` / `get_embeddings` / `get_context` (`local_embedding.py`), `add_document` / `add_vector` / `search` (`vector_index.py`), `extract_text` / `get_paragraphs` (`pdf_reader.py`), `load_ai_model` (`main.py`).
- Test functions are `test_<unit>_<behavior>`: `test_chunk_dump_matches_legacy_keys`, `test_chunk_frozen_and_hashable`, `test_tracer_chunk_to_store_roundtrip` (`tests/test_models.py`), `test_insert_get_roundtrip`, `test_two_instance_interleave_R1` (`tests/test_doc_store.py`), `test_corrupt_invalid_rejected_WR07`, `test_rename_yields_same_doc_id` (`tests/test_upload_validation.py`), `test_page_failure_isolated`, `test_hash_chunk_ids_stable_across_rename` (`tests/test_pdf_reader.py:141,176`).
- Private helpers use a single leading underscore: `_embed_one` (`local_embedding.py`), `_cosine_distance` / `_euclidean_distance` / `_dot_product` / `_magnitude` (`vector_index.py`), `_connect` / `_apply_migrations` (`doc_store.py:80,93`).
- Private state uses a single leading underscore: `_vector_dim`, `_distance_metric`, `_embedding_fn` (`vector_index.py`).
- `DocStore` public state is intentionally non-private: `self.db_path` (`doc_store.py:71`) — tests and `main.py` rely on it.

**Variables / attributes:**
- `snake_case` locals and attributes: `indexed_files`, `document_metadata`, `doc_ids`, `local_embedding`, `chat_history` (session keys, `main.py`), `page_chunks`, `pages_text`, `page_records` (`pdf_reader.py:24-26`), `groq_client`, `model_name` (`local_llm.py`), `validated`, `doc_id`, `existing_doc`, `page_records`, `doc_model`, `cache_dir` (`main.py:127,133-134,162,178,192`).
- Module constants are `UPPER_CASE` in new code — follow this for new config: `CONFIG_VERSION = "chunker-1000-200-pypdf"` (`models.py:12`), `MAX_FILE_MB = 50`, `MAX_PAGES = 500` (`upload_validation.py:14-15`), `SCHEMA_V1_DDL`, `MIGRATIONS` (`doc_store.py:14,54`).
- Legacy inline-literal style (`chunk_size=1000, chunk_overlap=200` in `pdf_reader.py:36-37`, `k=10` call sites, `max_tokens=1024`) is grandfathered — do not convert; use named constants only for new cross-module config.

**Types:**
- New code uses builtin generics (`str | Path`, `str | None`, `list[Chunk]`, `dict[str, Any]` — `doc_store.py:64,80,228,287`) and Pydantic `Field(...)` constraints. `typing.Any` appears only for the row-dict bridge (`doc_store.py:11,287`).
- `typing` generics (`List`, `Dict`, `Tuple`, `Optional`, `Any`) remain only in `vector_index.py`. `local_embedding.py` uses builtin generics sparingly. `main.py`, `local_llm.py` are mostly untyped except isolated hints.

## Code Style

**Formatting:**
- Ruff is the formatter AND linter of record (config in `pyproject.toml:1-11`). `line-length = 120`, `target-version = "py311"`. CI enforces **both** `ruff check .` and `ruff format --check .` (`.github/workflows/ci.yml:30-33`).
- 4-space indentation. `E501` (line length) is ignored in ruff config, so long f-strings/prompts are tolerated.
- Mixed quote style: double quotes for code/strings; Pydantic modules use `"""..."""` docstrings (`models.py:1-6`, `doc_store.py:1-7`, `upload_validation.py:1-6`); `local_llm.py`/`pdf_reader.py`/`main.py` helpers use terse `'''...'''` one-to-three-liners. When adding code, match the surrounding file rather than normalising repo-wide.

**Linting (must-follow):**
- Run `ruff check .` AND `ruff format --check .` before pushing — CI fails the build on any violation (`.github/workflows/ci.yml:30-33`). Verified clean with `ruff 0.15.12` (18 files formatted).
- Enabled rules: `select = ["E", "F", "W"]` (`pyproject.toml:6`); ignored: `E501` (long lines OK), `W291`/`W293` (trailing whitespace tolerated) (`pyproject.toml:7`).
- Per-file ignores: `scripts/*` ignores `E402` only (module-level import not at top — needed for the `sys.path.insert` bootstrap in `scripts/benchmark_baseline.py`). The old `tests/*` `F401`/`F841` exemption is **removed** — keep test imports minimal; unused imports in tests now fail CI.
- No mypy, no coverage gate in CI.

**Section banners:**
- Use the dashed banner comment to separate logical sections, with surrounding blank lines. Copy this exact shape when adding a section:
  ```python
  # ------------------------------------------------------------------
  # Sidebar — model status + document upload
  # ------------------------------------------------------------------
  ```
  Observed in `main.py` and `vector_index.py`, plus the `# Run` footer block (`main.py`, `vector_index.py:224-226`, `pdf_reader.py:138-140`).
- Test modules open with the same banner stating scope: `# Unit Tests for Canonical Models (models.py)` (`tests/test_models.py:1-5`), `# Unit Tests for DocStore (doc_store.py)` (`tests/test_doc_store.py:1-5`), `# Unit Tests for Upload Validation (upload_validation.py)` (`tests/test_upload_validation.py:1-5`), plus the pre-existing banners in `test_vector_index.py`, `test_pdf_reader.py`, `test_local_embedding.py`, `test_local_llm.py`, `conftest.py`. New test files must open with the same banner.

## Import Organization

**Order (observed, follow this):**
1. Standard library (`os`, `io`, `re`, `math`, `typing`, `json`, `sys`, `time`, `hashlib`, `sqlite3`, `pathlib`, `datetime`, `dataclasses`).
2. Third-party (`streamlit`, `dotenv`, `sentence_transformers`, `pypdf`, `langchain_text_splitters`, `groq`, `numpy`, `psutil`, `reportlab`, `pytest`, `pydantic`).
3. First-party / local modules (`models`, `doc_store`, `upload_validation`, `local_llm`, `local_embedding`, `pdf_reader`, `vector_index`).

**Examples:**
- `main.py:15-28` — stdlib block (`datetime`, `io`, `json`, `pathlib`), blank line, third-party (`dotenv`, `streamlit`), local block (`doc_store`, `local_embedding`, `local_llm`, `models`, `pdf_reader`, `upload_validation`).
- `doc_store.py:9-12` — stdlib (`pathlib`, `sqlite3`, `typing`), then local (`models`). Note: `from models import ...` is a flat top-level import, matching the no-packages convention.
- `models.py:8-9` — stdlib (`pathlib`), then `pydantic` (`BaseModel`, `ConfigDict`, `Field`).
- `upload_validation.py:8-11` — stdlib (`dataclasses`, `hashlib`, `io`), then `pypdf`.
- `pdf_reader.py:1-7` — `pathlib`, `re`, `pypdf`, blank, `langchain_text_splitters`, blank, `models` (`Chunk`, `Page`).
- `tests/conftest.py:6-9` — stdlib (`pathlib`), `unittest.mock`, third-party (`numpy`, `pytest`).
- `scripts/benchmark_baseline.py` — stdlib, then `sys.path.insert(0, REPO_ROOT)` bootstrap, then local imports. The deferred `from sentence_transformers import SentenceTransformer` inside `run_benchmark` is intentional (measure model-load time separately) — do not hoist it.

**Path aliases:**
- None. All imports are top-level absolute (`from vector_index import VectorIndex` in `local_embedding.py`, `from models import Chunk, Page` in `pdf_reader.py:7`).

**Exception to the rule:**
- `import io` is now hoisted to top level in `main.py:16` (the old inline `import io` inside the upload loop was removed in Phase 1). Hoist all new stdlib imports to the top-level block — there are no remaining sanctioned inline imports except the intentional deferred transformer import in the benchmark script.

## Pydantic Idioms (must-follow — Phase 1)

**Model declaration shape (`models.py:29-111`):**
```python
class Chunk(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")

    content: str = Field(..., min_length=1, description="Extracted chunk text content.")
    page: int = Field(..., ge=1, description="1-indexed source page number.")
    sha256: str = Field(..., pattern=r"^[0-9a-f]{64}$", description="...")
```
- `frozen=True` on immutable value objects (`BBox` in `models.py:34`, `Chunk` in `models.py:51`) — frozen models are hashable; pin with a hashability test (`test_chunk_frozen_and_hashable` in `tests/test_models.py:37-51`, which also asserts reassignment raises `ValidationError`).
- `extra="forbid"` on every model (`Chunk`, `Page`, `EvidenceElement`, `Document`) — pin with a `test_document_extra_forbidden`-style test asserting `pytest.raises(ValidationError, match="extra")` (`tests/test_models.py:54-66`).
- Field constraints, not validators: `min_length=1` for non-empty text (`models.py:53`), `ge=1` for 1-indexed pages (`models.py:55,73,89`), `ge=0` for counts (`models.py:75,77,107,111`), `pattern=r"^[0-9a-f]{64}$"` for SHA digests (`models.py:106`). Cross-field validators (`doc_id`↔`sha256` consistency, status literals) are a known gap (WR-05, `01-REVIEW.md:185-198`) — add them as `@field_validator`/`model_validator` without breaking the `extra="forbid"` contract.
- Every field carries a `description=` — new fields must include one.
- Pages are 1-indexed everywhere (`page_num = i + 1` in `pdf_reader.py:49`, `ge=1` in models). Never store 0-indexed page numbers.

**Dict-compat bridge (the rule that keeps legacy callers working):**
- Producers construct the model, then hand legacy callers a plain dict: `chunk_model.model_dump()` in `pdf_reader.py:86-94`. `model_dump()` on `Chunk` is a superset — the 4 legacy keys (`content`, `filename`, `page`, `chunk_id`) keep identical values, pinned by `test_chunk_dump_matches_legacy_keys` (`tests/test_models.py:13-34`).
- Consumers accept the superset: `LocalEmbedding.build_index` and `VectorIndex` pass extra keys through as stored metadata; `Chunk.model_validate(p)` rebuilds from stored dicts (`doc_store.py:293`). New retrieval/indexing code must tolerate extra keys — never assert exact key sets on chunk dicts.
- SQLite round-trips go through `model_validate(dict(row))` for reads (`doc_store.py:161,181,193`) and attribute access for writes (`doc.doc_id`, `doc.sha256`, … in `doc_store.py:130-140`). `bbox` is the special case: serialised via `model_dump_json()` on write (`doc_store.py:252`), deserialised via `BBox.model_validate_json()` on read (`doc_store.py:290`), `None` when the column is NULL.
- JSON round-trips use `model_dump_json()` / `model_validate_json()` — pinned by `test_json_roundtrip` (`tests/test_models.py:92-107`).
- Legacy-dict adaptation pattern for tests/producers: `Chunk(doc_id=..., extraction="pypdf", **legacy_data)` (`tests/test_models.py:220-225`).

**Pure helpers in `models.py`:**
- `CONFIG_VERSION` (`models.py:12`) versions the extraction/chunking policy; cache paths embed it (`cache_dir_for` in `models.py:15-26` returns `base / sha256 / CONFIG_VERSION`). Pinned by `test_config_version_and_cache_dir_helper` (`tests/test_models.py:146-152`). Bump `CONFIG_VERSION` when chunking policy changes; never reuse a version string for a different policy.

## SQLite Idioms (must-follow — `doc_store.py`)

**Per-operation connections:**
- Every public method opens its own connection via `self._connect()` (`doc_store.py:80-91`: `timeout=5.0`, `row_factory = sqlite3.Row`, `PRAGMA journal_mode=WAL`, `PRAGMA busy_timeout=5000`), uses it inside `with self._connect() as conn:`, commits explicitly. There are no long-lived connections and no connection pooling — this is what makes `DocStore` safe under Streamlit's rerun-every-interaction model and is pinned by `test_two_instance_interleave_R1` (`tests/test_doc_store.py:92-123`).
- Known gap (WR-01, `01-REVIEW.md:123-132`): `with conn:` commits/rolls back but does **not** close the connection — migrate to `contextlib.closing` when touching connection code.

**Schema versioning:**
- DDL lives in `SCHEMA_V1_DDL` list (`doc_store.py:14-52`), wired through `MIGRATIONS: dict[int, list[str]]` (`doc_store.py:54-56`), applied by `_apply_migrations` comparing `PRAGMA user_version` (`doc_store.py:93-106`, prints `[DocStore] Applied migration v{version}`). New schema changes add a `2: [...]` entry plus `PRAGMA user_version = 2` handling — never edit `SCHEMA_V1_DDL` in place for a breaking change. Pinned by `test_user_version_set` (`tests/test_doc_store.py:126-134`).

**Query shape:**
- All SQL is parameterized (`?` placeholders, never f-strings) — `doc_store.py:118-141,205-226,240-270,283`. Tables use `TEXT PRIMARY KEY` (`doc_id`, `chunk_id`) and composite `PRIMARY KEY (doc_id, page_num)` for pages (`doc_store.py:35`).
- Upserts use `ON CONFLICT(...) DO UPDATE SET` (`doc_store.py:118-126` for documents, `doc_store.py:205-213` for pages, `doc_store.py:240-247` for chunks). `sha256` carries a `UNIQUE` constraint for dedup (`doc_store.py:19`); the `IntegrityError`-on-reupload behaviour is pinned by `test_sha_unique_violation_on_reupload` (`tests/test_doc_store.py:40-66`) but no production caller handles it yet (WR-03, `01-REVIEW.md:154-165`).
- Ordering: `list_documents` is `ORDER BY upload_time DESC` (`doc_store.py:191`); `get_chunks_for_doc` is `ORDER BY page ASC, chunk_id ASC` (`doc_store.py:283`) — lexical chunk-ID ordering scrambles 10+ chunks per page (WR-06, `01-REVIEW.md:200-208`); zero-pad sequences or order by `char_start`/`rowid` when fixing.

**Type guards:**
- Public methods fail fast on wrong types before touching the DB: `isinstance(doc, Document)` / `isinstance(page, Page)` / per-element `isinstance(c, Chunk)` with `TypeError(f"Expected X instance, got {type(...).__name__}")` (`doc_store.py:115-116,202-203,250-251`), `isinstance(chunks, list)` (`doc_store.py:235-236`), `isinstance(doc_id, str)` / `isinstance(sha256, str)` (`doc_store.py:153-154,173-174`). `record_chunks([])` returns early without opening a transaction (`doc_store.py:237-238`). New `DocStore` methods must follow this guard-first shape.
- Reads return models or `None` (`get_document`, `get_by_sha` return `None` on miss — `doc_store.py:159-160,179-180`); lists return `list[Document]` / `list[Chunk]`, never `None`.

**Test isolation for stores:**
- `DocStore` tests take `tmp_path` and construct a fresh `DocStore(tmp_path / "<name>.db")` per test (`tests/test_doc_store.py:13-16`). Never point tests at `data/documents.db`. Direct-SQL assertions use `store._connect()` (`tests/test_doc_store.py:84-89,131-134`) — the only sanctioned white-box connection access outside `DocStore`.

## Upload Validation Idioms (must-follow — `upload_validation.py:61-107`)

**Fail-fast order (do not reorder):**
1. `%PDF` magic-byte prefix check → `ValueError("Not a valid PDF: missing %PDF header — {filename}.")` (`upload_validation.py:76-77`).
2. Size cap (`len(raw) > MAX_FILE_MB * 1024 * 1024`) → `ValueError("File too large ({mb:.1f} MB > ...)")` (`upload_validation.py:80-84`).
3. `pypdf.PdfReader(io.BytesIO(raw))` probe → page count → cap (`num_pages > MAX_PAGES`) → `ValueError("Too many pages (...)")`; probe exceptions chain via `raise ValueError(f"Unreadable PDF ({err}) — {filename}.") from err` (`upload_validation.py:87-94`).
4. Hash + `doc_id` derivation only after all checks pass (`upload_validation.py:97-106`).
- New validation steps slot into this order (cheap syntactic checks before expensive parsing, hashing last). All `ValueError` messages end with `— {filename}` so the UI can display them verbatim via `st.error(str(e))` (`main.py:128-130`).
- Constants `MAX_FILE_MB` / `MAX_PAGES` are module-level and monkeypatchable — the page-cap test patches the `pypdf.PdfReader` seam (`tests/test_upload_validation.py:61-76`); prefer patching `MAX_FILE_MB` small over allocating real oversize payloads for new size tests (IN-05, `01-REVIEW.md:264-270`).

**Hashing identity:**
- `sha256_bytes` hashes in 1 MiB slices (`upload_validation.py:29-32`); `doc_id_for(sha)` returns `f"doc_{sha[:16]}"` (`upload_validation.py:35-45`); `ValidatedUpload` is `@dataclass(frozen=True)` with `doc_id/filename/sha256/size_bytes/num_pages` (`upload_validation.py:48-58`). Rename-stability (`same bytes + different filename → same sha/doc_id`) is pinned by `test_rename_yields_same_doc_id` (`tests/test_upload_validation.py:40-51`).
- Chunk IDs derive from the content hash, not the filename: `f"{sha12}_p{page_num}_{j}"` with filename fallback when no hash is supplied (`pdf_reader.py:41-42,84-85`, `main.py:159-160`). Pinned by `test_hash_chunk_ids_stable_across_rename` (`tests/test_pdf_reader.py:176-202`).

## Error Handling

**Guard-clause validation (primary pattern — `vector_index.py`):**
- Fail fast with `TypeError` for wrong types and `ValueError` for bad values, before mutating state:
  ```python
  # `vector_index.py`, `doc_store.py:115-116`
  if not isinstance(vector, list) or not all(isinstance(x, (int, float)) for x in vector):
      raise TypeError("Vector must be a list of numbers.")
  if k <= 0:
      raise ValueError("k must be a positive integer.")
  ```
- Full guard inventory to mirror: metric whitelist, missing embedding fn, non-dict document / missing `content` key / non-string content, dimension lock-in and mismatch, bad query type, vector-length checks in every distance helper.
- Empty-store behaviour: `search()` returns `[]` instead of raising when nothing is indexed.
- Tests assert every guard with `pytest.raises(<Type>, match="<message fragment>")` — see `test_add_vector_guards` (`tests/test_vector_index.py`) and `test_vector_index_initialization`. New guards must add a matching `pytest.raises` case with the exact message fragment.

**Pydantic validation errors:**
- Model misuse surfaces as `pydantic.ValidationError`, not `TypeError`/`ValueError`. Tests assert it directly: `with pytest.raises(ValidationError): chunk.content = "Mutated text"` (`tests/test_models.py:50-51`), `match="extra"` for forbidden extras (`tests/test_models.py:57`), bare `pytest.raises(ValidationError)` for bad SHA patterns (`tests/test_models.py:71-89`). New model constraints need a matching `ValidationError` test.

**Optional-dependency pattern (`local_llm.py:6-9,19-21`):**
```python
try:
    from groq import Groq
except ImportError:
    Groq = None
# ... later, in AiModel.__init__:
if not Groq:
    raise ImportError("groq package is missing. Please run `pip install groq`.")
```
- Use this shape for any new optional third-party import: `try/except ImportError → None` at top, explicit `ImportError` with install hint at use site.

**Config-failure pattern:**
- Missing `GROQ_API_KEY` raises `ValueError` with remediation text naming both secret locations. New required-config checks must raise with the same "what + where to set it" message shape. Covered by `test_ai_model_missing_key_raises` (`tests/test_local_llm.py`), which deletes the env var via `monkeypatch.delenv("GROQ_API_KEY", raising=False)`.

**UI-level handling (`main.py:126-130`):**
- Per-file `try/except ValueError` around `validate_pdf_bytes`, reporting via `st.error(str(e))` then `continue` so one bad PDF never aborts the batch. New per-document processing must use this isolate-and-continue shape, never a bare `except:`. Known gap (CR-02, `01-REVIEW.md:75-99`): `PdfReader(...)` construction sits outside the guard — extend the try to cover construction + extraction + chunk validation.

**Page-level fault isolation (`pdf_reader.py:48-105`):**
- Per-page `try/except` around `page.extract_text()` records `Page(status="failed", error=str(err))` and `continue`s; empty pages record `Page(status="empty")` (`pdf_reader.py:50-76`). Pinned by `test_page_failure_isolated` (`tests/test_pdf_reader.py:141-174`, monkeypatches `extract_text` to fail on page 2 only). Known gap (WR-02, `01-REVIEW.md:141-152`): `split_text` + `Chunk(...)` construction sit outside the guard — extend it or pre-filter whitespace-only splits.

**Script-level handling (`scripts/benchmark_baseline.py`):**
- Fail fast with a message + `sys.exit(1)` when a prerequisite is missing (corpus PDF absent). Wrap new script entry points in `if __name__ == "__main__":` calling a single `run_*()` function, mirroring `run_benchmark()`.

**Defensive indexing:**
- `paragraphs[-1]["page"] if paragraphs else 0` guards empty PDFs; `if chat_history:` / `if last_user_msgs:` guards history contextualisation; zero-magnitude vectors return `0.0`/`1.0` instead of dividing by zero. Preserve these guards when touching the same code. Zero-magnitude behaviour is pinned by `test_zero_magnitude_vector` (`tests/test_vector_index.py`).

## Logging

**Framework:** `print()` to stdout/stderr only. No `logging` module, no log levels, no structured logging.

**Patterns:**
- Lifecycle prints with module prefix: `print(f"[LocalEmbedding] Loading ...")`, `print("[LocalEmbedding] Model ready.")`, `print(f"Successfully extracted text from {self.filename}...")` (`pdf_reader.py:109`), `print(f"[UploadValidation] Validated {filename} ({doc_id}, {num_pages} pages, {size_bytes} bytes)")` (`upload_validation.py:100`), `print(f"[DocStore] Applied migration v{version} to {self.db_path.name}")` (`doc_store.py:106`).
- Benchmark progress prints use numbered-stage headers (`[1/4]`, `[2/4]`, …) plus `[Memory]` / `[Output]` tags. New long-running scripts must use the same staged-print shape.
- Corpus generator prints per-file byte sizes at completion.
- User-facing feedback goes through Streamlit, never `print`: `st.error` / `st.info` / `st.success` / `st.status` / `st.write` / `st.warning` / `st.progress` (`main.py:115-222`). Rule: `print()` for developer diagnostics, `st.*` for anything the user should see.
- Tests assert behaviour, never log output — no `caplog`/`capsys` usage in the suite.

## Comments

**When to comment:**
- Explain *why Streamlit behaves unusually*, not what the code does. Exemplar: why the whole script reruns and why session state is the only persistence (`main.py`). ## Function Design

**Size:**
- Small single-purpose methods (5–25 lines). Largest functions are UI layout blocks in `main.py` (sidebar upload loop ~100 lines, chat handler) — these are sequential Streamlit layouts, not logic to extract, unless adding genuinely new UI sections.
- Test functions are single-behavior (5–35 lines each); one `test_*` per behavior, not one mega-test per class. The tracer test (`test_tracer_chunk_to_store_roundtrip`, `tests/test_models.py:155-206`) is the sanctioned exception — it spans Reader → Chunk → DocStore deliberately as a contract slice.

**Parameters:**
- Keyword-friendly with sane defaults: `prompt: str = "tell me what is this pdf about", local_embedding=None, chat_history=None` (`local_llm.py`); `k: int = 3` (`local_embedding.py`, `vector_index.py`); `model_name: str = "all-MiniLM-L6-v2", distance_metric: str = "cosine"`. New retrieval parameters must default so existing call sites keep working.
- `PdfReader.__init__(self, file_or_path, filename=None)` accepts a path string, bytes stream, or file object (`pdf_reader.py:12-23`); `extract_text(doc_id=None, sha12=None)` falls back to filename-derived identity (`pdf_reader.py:41-42`) — callers must pass the validated `doc_id`/`sha12` (`main.py:159-160`).
- `VectorIndex.search(query: Any, ...)` accepts a string or a precomputed vector; `LocalEmbedding.build_index(chunks: list)` accepts `list[str]` or `list[dict]`. Extend with the same accept-both-types + normalise-early shape.
- `DocStore.__init__(self, db_path: str | Path)` accepts both path types and creates parent dirs (`doc_store.py:64-74`).
- Fixtures take `monkeypatch` / `tmp_path` and return the handle for assertions: `mock_groq_client(monkeypatch) -> mock_client`, `mock_sentence_transformer(monkeypatch) -> mock_model` (`tests/conftest.py:18-81`). Request fixtures by name as test args (`def test_ai_model_prompt_assembly(fake_env_groq_key, mock_groq_client):` in `tests/test_local_llm.py`).

**Return values:**
- Data methods return plain containers or models: `list[dict]` chunks with `content`/`filename`/`page`/`chunk_id` keys (`pdf_reader.py`), `list[tuple[dict, float]]` of `(document, distance)` sorted ascending (`vector_index.py`), joined context string (`local_embedding.py`), `Document | None` on store misses (`doc_store.py:143,163`), `list[Document]` / `list[Chunk]` on listings (`doc_store.py:183,272`), `ValidatedUpload` from `validate_pdf_bytes` (`upload_validation.py:101-107`).
- Generation is a token generator (`yield chunk.choices[0].delta.content` in `local_llm.py`) consumed by `st.write_stream`, which returns the full string (`main.py:295`). New LLM entry points must yield strings (not return a completed string) to preserve streaming. Pinned by `test_ai_model_streaming_yield` (`tests/test_local_llm.py`).
- No `None`-on-error: failures raise, empty results return `[]`/`None`-on-miss (`vector_index.py`, `local_embedding.py`, `doc_store.py:159-160`).
- Corpus builders return `None` and write to disk; `generate_all_corpus_files() -> dict[str, Path]` maps names to paths.

## Module Design

**Exports:**
- Single public class per module, imported by name — no `__all__`, no factories, no re-exports. Wire new cross-module dependencies the same way (`from x import Y` at top level, e.g. `main.py:23-28`).
- `models.py` exports models + `CONFIG_VERSION` + `cache_dir_for`; `upload_validation.py` exports `validate_pdf_bytes` + `sha256_bytes` + `doc_id_for` + `ValidatedUpload` + caps; `doc_store.py` exports `DocStore` + `SCHEMA_V1_DDL` + `MIGRATIONS`.
- Benchmark script exposes `run_benchmark()` + `get_current_rss_mb()` and runs only under `if __name__ == "__main__":`. Corpus module exposes `generate_all_corpus_files()` under the same guard. Importing these modules must never trigger work.

**Barrel files:**
- None and not wanted: the flat layout means a new module is just a new root-level file plus an import where used. New test files are new `tests/test_*.py` files (auto-discovered via `python_files = ["test_*.py"]` in `pyproject.toml:15`).

## Test Conventions (must-follow)

**Fixtures — use `tests/conftest.py`, do not re-mock inline:**
- `fake_env_groq_key` — sets `GROQ_API_KEY` via `monkeypatch.setenv` to an obviously inert value (`tests/conftest.py:12-15`). Use in every `AiModel` construction test.
- `mock_groq_client` — patches the exact symbol `AiModel` calls (`local_llm.Groq` via `monkeypatch.setattr(local_llm, "Groq", lambda api_key=None: mock_client)`) and yields 5 canned tokens `["This ", "is ", "a ", "grounded ", "answer."]` through `choices[0].delta.content` (`tests/conftest.py:18-48`). Assert via `mock_client.chat.completions.create.call_args[1]` (`messages`, `model`, `stream`).
- `mock_sentence_transformer` — patches the exact symbol `LocalEmbedding` calls (`local_embedding.SentenceTransformer`), returns deterministic 384-dim L2-normalised `float32` vectors keyed off text length (`tests/conftest.py:51-81`). Assert `store._vector_dim == 384` after `build_index`.
- `sample_pdf_path` — resolves `tests/data/corpus/clean_digital.pdf` (`tests/conftest.py:84-88`). New PDF tests should prefer the fixture over a local `CORPUS_DIR` constant (`tests/test_upload_validation.py:13` still duplicates it — do not copy that).
- `tmp_path` (pytest builtin) — every `DocStore` test builds an isolated DB under `tmp_path` (`tests/test_doc_store.py:13-16`); the tracer test uses `tmp_path / "tracer.db"` (`tests/test_models.py:186`). Never write test DBs to the repo tree.
- Tests never hit network, GPU, or disk-external resources: Groq is mocked, `SentenceTransformer` is mocked, corpus PDFs are generated locally by `generate_corpus.py` and read from disk. The only unmocked heavy path is `scripts/benchmark_baseline.py`, which intentionally loads the real model (not a test).

**Mocking rules:**
- Mock at the seam the production code calls (module attribute), not the library root: `local_llm.Groq`, not `groq.Groq`; `local_embedding.SentenceTransformer`, not `sentence_transformers.SentenceTransformer`. Use `monkeypatch.setattr` (auto-reverted), never manual patch/unpatch. The page-cap test patches `pypdf.PdfReader` globally (`tests/test_upload_validation.py:61-76`) — prefer patching the `pypdf` reference inside `upload_validation` if tests ever parallelise (IN-05, `01-REVIEW.md:264-270`).
- `MagicMock` for injected collaborators: `mock_embedding = MagicMock(); mock_embedding.get_context.return_value = "..."`. Assert collaboration with `assert_called_once()` and inspect `call_args`.
- Page-failure injection: monkeypatch the page object's `extract_text` to raise on one page only, then assert the remaining pages still extract and record (`tests/test_pdf_reader.py:141-174`) — the model for all future fault-isolation tests.
- What NOT to mock: `VectorIndex` math (pure stdlib — test directly with hand-computed vectors); `RecursiveCharacterTextSplitter` behaviour (assert observable chunk size/metadata); corpus PDFs on disk (read the real generated files); `hashlib.sha256` (compare `sha256_bytes` against it directly, `tests/test_upload_validation.py:79-84`).
- Known coupling (accepted): `tests/test_vector_index.py` binds to private API (`_cosine_distance`, `_euclidean_distance`, `_distance_metric`, `_vector_dim`) — white-box by design for the math-guard suite. `tests/test_doc_store.py` uses `store._connect()` for direct-SQL assertions — the only sanctioned white-box DB access. Do not extend private-API coupling to other modules.

**Assertion idioms:**
- Float math: `assert pytest.approx(actual, abs=1e-5) == expected`.
- Errors: `with pytest.raises(<ExcType>, match="<message fragment>"):` — `TypeError`/`ValueError` for guards, `ValidationError` for models, `sqlite3.IntegrityError` for the SHA-unique constraint, `ValueError match="Not a valid PDF: missing %PDF header"` / `match="File too large"` / `match="Too many pages"` for upload validation.
- Model equality: `assert retrieved == doc` / `assert retrieved_chunks[0] == chunk` (Pydantic `__eq__`, `tests/test_models.py:201-206`, `tests/test_doc_store.py:32-33`).
- Corpus preconditions: `assert pdf_path.exists(), "Corpus file ... must exist"` before reading — failure message tells the runner to run the generator first.
- Streaming: `tokens = list(generator)` then compare exact token list and joined string.
- Keep test imports minimal — the old `tests/*` ruff `F401`/`F841` exemption is gone, so unused imports now fail CI.

**Corpus generation rules:**
- `tests/data/corpus/generate_corpus.py` is deterministic, offline, fixed filenames — use `reportlab` only (stdlib + reportlab, no network). Scanned-sample generator must use only vector rects (no `drawString`) so the zero-text property the scanned test depends on is structural. Corrupt fixture must be raw invalid bytes, not a valid PDF. Regenerate via `python tests/data/corpus/generate_corpus.py` (CI runs this before pytest).

## Streamlit Idioms (must-follow)

- `st.set_page_config(...)` is the very first Streamlit call (`main.py`) — never insert a Streamlit call above it.
- Initialise all `st.session_state` keys via the key/default loop; add new keys there, never lazily mid-layout. Phase 1 added `doc_ids: set` alongside `indexed_files`, `document_metadata`, `local_embedding`, `chat_history`.
- Heavy singletons go behind `@st.cache_resource`; per-`load_dotenv()`-before-read ordering inside the cached function matters because `AiModel.__init__` reads the env.
- Upload-loop staged pattern (`main.py:115-222`): `with st.status("Processing documents…", expanded=True)` wrapper → per-file numbered steps (`# 1.` single `getvalue()` read → `# 2.` `validate_pdf_bytes` with `st.write("Validating …")` → `# 3.` `get_by_sha` dedup check with `st.info` skip → `# 4.` extraction with `st.progress(0.0)` updated per page (`main.py:154,166`) and `st.warning` per failed page → `# 5.` `build_index` → `# 6.` `upsert_document` → `# 7.` best-effort `.cache/` write guarded by `try/except OSError` → `# 8.` session-state update + `st.success`). New upload steps slot into this numbering; per-page progress uses `progress_bar.progress((idx + 1) / max(1, len(page_records)))`.
- Render pattern: `with st.sidebar:` layout, `st.status` for staged work with `.update(label=..., state="complete", expanded=False)` on completion, `st.chat_message` + `st.markdown` for history replay, `st.chat_input(..., disabled=(...))` for gated input, `response_stream → st.write_stream(response_stream) → append to history`.
- State mutation ends with `st.rerun()` after batch updates (`main.py:216` after new PDFs indexed).
- Identity in session state is hash-based: `doc_ids: set[str]` (`doc_<sha16>`) is the dedup key, `document_metadata[filename]` carries `doc_id/upload_time/pages/chunks` display fields. New session keys for documents must key off `doc_id`, never bare filename.
- Missing-key test validity depends on no `secrets.toml` in the test env (`st.secrets[…]` raising `FileNotFoundError`) — never commit a secrets file that would silently change this path.

## Config Patterns (must-follow)

- `load_dotenv()` is called inside the cached loader, and `AiModel` reads `st.secrets["GROQ_API_KEY"]` first with `except (KeyError, FileNotFoundError)` fallback to `os.environ.get("GROQ_API_KEY")`. New secrets must follow this exact precedence: `st.secrets` → `.env`/`environ` → raise `ValueError` naming both locations.
- Pytest config lives in `pyproject.toml:13-20`: `testpaths = ["tests"]`, `python_files = ["test_*.py"]`, `python_functions = ["test_*"]`, `filterwarnings` ignoring `UserWarning`/`DeprecationWarning`.
- Runtime deps are pinned in `requirements.txt` (now 8 lines: 6 original + `numpy>=1.26.0,<3.0.0` range + `pydantic==2.11.9` exact). Test-only deps live in `requirements-test.txt` (`pytest`, `reportlab`, `ruff`, `psutil`, all minimum-version `>=` pins) and are installed via `pip install -r requirements-test.txt` in CI (`.github/workflows/ci.yml:28`) — never add test-only packages to `requirements.txt`.
- Never commit secrets: `.env` is gitignored (`.gitignore:1`); existence only is noted, contents are never read or quoted. The `fake_env_groq_key` value is an obviously inert mock string (`tests/conftest.py:15`).
- `data/` is gitignored (`.gitignore:10`) — the production `data/documents.db` never commits. `.cache/` is NOT yet gitignored (WR-07, `01-REVIEW.md:210-220`) — add it when touching `.gitignore`.
