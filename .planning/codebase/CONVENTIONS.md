# Coding Conventions

**Analysis Date:** 2026-10-11

## Naming Patterns

**Files:**
- Flat `snake_case.py` modules at repo root, one class (or one concern) per file: `main.py` (Streamlit entry point), `local_llm.py`, `local_embedding.py`, `vector_index.py`, `pdf_reader.py`, `models.py` (Pydantic schemas), `doc_store.py` (SQLite store), `upload_validation.py` (upload guards + hashing).
- Test files live under `tests/` as `test_<module>.py`: `tests/test_vector_index.py`, `tests/test_pdf_reader.py`, `tests/test_local_embedding.py`, `tests/test_local_llm.py`, `tests/test_models.py`, `tests/test_doc_store.py`, `tests/test_upload_validation.py`. Shared fixtures in `tests/conftest.py`; package marker `tests/__init__.py` (single docstring).
- Utility scripts live under `scripts/`: `scripts/benchmark_baseline.py`. Synthetic corpus generator at `tests/data/corpus/generate_corpus.py`; generated corpus PDFs are build artifacts regenerated by CI, not hand-written fixtures.
- Test-only dependencies live in `requirements-test.txt` (`pytest`, `reportlab`, `ruff`, `psutil`); runtime pins stay in `requirements.txt` (includes `numpy>=1.26.0,<3.0.0` and `pydantic==2.11.9`).
- No packages, no barrel files. Imports are direct module imports (e.g. `from local_llm import AiModel` in `main.py`, `from doc_store import DocStore` in `main.py`, `from models import BBox, Chunk, Document, Page` in `doc_store.py`).

**Classes:**
- `PascalCase`, one public class per module: `AiModel` (`local_llm.py`), `LocalEmbedding` (`local_embedding.py`), `VectorIndex` (`vector_index.py:15`), `PdfReader` (`pdf_reader.py`), `DocStore` (`doc_store.py:59`).
- Pydantic models in `models.py` are `PascalCase`: `BBox` (`models.py:33`), `Chunk` (`models.py:54`), `Page` (`models.py:75`), `EvidenceElement` (`models.py:90`), `Document` (`models.py:108`).
- `ValidatedUpload` is a frozen dataclass, not a Pydantic model (`upload_validation.py`) — it is a throwaway validation result, never persisted.
- Test-only doubles use `Mock`-prefixed class names defined inside fixtures, never at module scope: `MockDelta` / `MockChoice` / `MockChunk` inside `mock_groq_client` (`tests/conftest.py`); `StubReader` / `ZeroPageReader` defined inside page-cap tests (`tests/test_upload_validation.py`).

**Functions / methods:**
- `snake_case` throughout. Phase 1 examples: `cache_dir_for` (`models.py:17`), `upsert_document` / `get_document` / `get_by_sha` / `list_documents` / `record_page` / `record_chunks` / `get_chunks_for_doc` (`doc_store.py`), `sha256_bytes` / `doc_id_for` / `validate_pdf_bytes` (`upload_validation.py`), `get_page_records` (`pdf_reader.py`), `extract_text(doc_id=None, sha12=None)` (`pdf_reader.py`).
- Established examples: `ask_a_question_from_pdf_stream` (`local_llm.py`), `build_index` / `get_embeddings` / `get_context` (`local_embedding.py`), `add_document` / `add_vector` / `search` (`vector_index.py`), `extract_text` / `get_paragraphs` (`pdf_reader.py`), `load_ai_model` (`main.py`).
- Test functions are `test_<unit>_<behavior>`: `test_chunk_dump_matches_legacy_keys`, `test_chunk_frozen_and_hashable`, `test_tracer_chunk_to_store_roundtrip`, `test_cache_dir_for_traversal_rejected`, `test_bbox_invalid_coordinates`, `test_document_invalid_doc_id_rejected`, `test_literal_status_validation` (`tests/test_models.py`), `test_restore_chunks_to_embedding_from_doc_store`, `test_upsert_document_updates_size_and_time`, `test_record_chunks_full_column_update_on_conflict` (`tests/test_doc_store.py`), `test_zero_page_pdf_rejected`, `test_doc_id_for_invalid_sha_rejected` (`tests/test_upload_validation.py`), `test_page_failure_isolated`, `test_hash_chunk_ids_stable_across_rename` (`tests/test_pdf_reader.py`).
- Private helpers use a single leading underscore: `_embed_one` (`local_embedding.py`), `_cosine_distance` / `_euclidean_distance` / `_dot_product` / `_magnitude` (`vector_index.py`).
- Private state uses a single leading underscore: `_vector_dim`, `_distance_metric`, `_embedding_fn` (`vector_index.py`).
- `DocStore` public state is intentionally non-private: `self.db_path` (`doc_store.py`) — tests and `main.py` rely on it. `db_path` is normalised via `Path(db_path).resolve()` with parents created unconditionally (`doc_store.py`).

**Variables / attributes:**
- `snake_case` locals and attributes: `indexed_files`, `document_metadata`, `doc_ids`, `local_embedding`, `chat_history` (session keys, `main.py`), `page_chunks`, `pages_text`, `page_records` (`pdf_reader.py`), `groq_client`, `model_name` (`local_llm.py`), `validated`, `doc_id`, `existing_doc`, `page_records`, `doc_model`, `cache_dir`, `now_iso`, `display_time`, `chunk_models` (`main.py`).
- Module constants are `UPPER_CASE` in new code — follow this for new config: `CONFIG_VERSION = "chunker-1000-200-pypdf"` (`models.py:14`), `MAX_FILE_MB = 50`, `MAX_PAGES = 500` (`upload_validation.py`), `SCHEMA_V1_DDL`, `MIGRATIONS` (`doc_store.py`).
- Legacy inline-literal style (`chunk_size=1000, chunk_overlap=200` in `pdf_reader.py`, `k=10` call sites, `max_tokens=1024`) is grandfathered — do not convert; use named constants only for new cross-module config.

**Types:**
- New code uses builtin generics (`str | Path`, `str | None`, `list[Chunk]`, `dict[str, Any]` — `doc_store.py`) plus `typing.Literal` for closed vocabularies (`Page.status: Literal["ok","empty","failed"]` in `models.py:84`, `EvidenceElement.kind: Literal["text","table","chart","image"]` in `models.py:100`, `Document.status: Literal["pending","indexed","failed"]` in `models.py:121`) and `collections.abc.Generator` for the `_connect` contextmanager (`doc_store.py`). `typing.Any` appears only for the row-dict bridge (`doc_store.py`).
- `typing` generics (`List`, `Dict`, `Tuple`, `Optional`, `Any`) remain only in `vector_index.py`. `local_embedding.py` uses builtin generics sparingly. `main.py`, `local_llm.py` are mostly untyped except isolated hints.

## Code Style

**Formatting:**
- Ruff is the formatter AND linter of record (config in `pyproject.toml:1-11`). `line-length = 120`, `target-version = "py311"`. CI enforces **both** `ruff check .` and `ruff format --check .` (`.github/workflows/ci.yml:30-33`).
- 4-space indentation. `E501` (line length) is ignored in ruff config, so long f-strings/prompts are tolerated.
- Mixed quote style: double quotes for code/strings; Pydantic modules use `"""..."""` docstrings (`models.py:1-6`, `doc_store.py`, `upload_validation.py`); `local_llm.py`/`pdf_reader.py`/`main.py` helpers use terse `'''...'''` one-to-three-liners. When adding code, match the surrounding file rather than normalising repo-wide.

**Linting (must-follow):**
- Run `ruff check .` AND `ruff format --check .` before pushing — CI fails the build on any violation (`.github/workflows/ci.yml:30-33`). Verified clean with `ruff 0.15.12` (18 files formatted, 0 errors).
- Enabled rules: `select = ["E", "F", "W"]` (`pyproject.toml:6`); ignored: `E501` (long lines OK), `W291`/`W293` (trailing whitespace tolerated) (`pyproject.toml:7`).
- Per-file ignores: `scripts/*` ignores `E402` only (module-level import not at top — needed for the `sys.path.insert` bootstrap in `scripts/benchmark_baseline.py`). There is no `tests/*` exemption — keep test imports minimal; unused imports in tests fail CI.
- No mypy, no coverage gate in CI.

**Section banners:**
- Use the dashed banner comment to separate logical sections, with surrounding blank lines. Copy this exact shape when adding a section:
  ```python
  # ------------------------------------------------------------------
  # Sidebar — model status + document upload
  # ------------------------------------------------------------------
  ```
  Observed in `main.py` and `vector_index.py`.
- Test modules open with the same banner stating scope: `# Unit Tests for Canonical Models (models.py)` (`tests/test_models.py`), `# Unit Tests for DocStore (doc_store.py)` (`tests/test_doc_store.py`), `# Unit Tests for Upload Validation (upload_validation.py)`, plus the pre-existing banners in `test_vector_index.py`, `test_pdf_reader.py`, `test_local_embedding.py`, `test_local_llm.py`, `conftest.py`. New test files must open with the same banner.

## Import Organization

**Order (observed, follow this):**
1. Standard library (`os`, `io`, `re`, `math`, `typing`, `json`, `sys`, `time`, `hashlib`, `sqlite3`, `pathlib`, `datetime`, `dataclasses`, `contextlib`, `collections.abc`).
2. Third-party (`streamlit`, `dotenv`, `sentence_transformers`, `pypdf`, `langchain_text_splitters`, `groq`, `numpy`, `psutil`, `reportlab`, `pytest`, `pydantic`).
3. First-party / local modules (`models`, `doc_store`, `upload_validation`, `local_llm`, `local_embedding`, `pdf_reader`, `vector_index`).

**Examples:**
- `main.py:15-29` — stdlib block (`datetime`, `io`, `json`, `pathlib`, `sqlite3`), blank line, third-party (`dotenv`, `streamlit`), local block (`doc_store`, `local_embedding`, `local_llm`, `models`, `pdf_reader`, `upload_validation`). `import sqlite3` at top level exists solely for the `except sqlite3.IntegrityError` dedup-race guard (`main.py:218`).
- `doc_store.py` — `collections.abc.Generator` + `contextlib.contextmanager` first (for the `@contextmanager _connect`), then stdlib (`pathlib`, `sqlite3`, `typing`), then local (`models`). Note: `from models import ...` is a flat top-level import, matching the no-packages convention.
- `models.py:8-11` — stdlib (`pathlib`, `re`), `typing.Literal`, then `pydantic` (`BaseModel`, `ConfigDict`, `Field`, `model_validator`).
- `upload_validation.py` — stdlib (`dataclasses`, `hashlib`, `io`, `re`), then `pypdf`.
- `pdf_reader.py` — `pathlib`, `re`, `pypdf`, blank, `langchain_text_splitters`, blank, `models` (`Chunk`, `Page`).
- `tests/conftest.py` — stdlib (`pathlib`), `unittest.mock`, third-party (`numpy`, `pytest`).
- `scripts/benchmark_baseline.py` — stdlib, then `sys.path.insert(0, REPO_ROOT)` bootstrap, then local imports. The deferred `from sentence_transformers import SentenceTransformer` inside `run_benchmark` is intentional (measure model-load time separately) — do not hoist it.

**Path aliases:**
- None. All imports are top-level absolute (`from vector_index import VectorIndex` in `local_embedding.py`, `from models import Chunk, Page` in `pdf_reader.py`).

**Exception to the rule:**
- All stdlib imports are hoisted to top level (the old inline `import io` inside the upload loop was removed in Phase 1). There are no sanctioned inline imports except the intentional deferred transformer import in the benchmark script.

## Pydantic Idioms (must-follow — `models.py`)

**Model declaration shape (`models.py:33-131`):**
```python
class Chunk(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")

    content: str = Field(..., min_length=1, description="Extracted chunk text content.")
    page: int = Field(..., ge=1, description="1-indexed source page number.")
    sha256: str = Field(..., pattern=r"^[0-9a-f]{64}$", description="...")
```
- `frozen=True` on immutable value objects (`BBox` in `models.py:38`, `Chunk` in `models.py:61`) — frozen models are hashable; pin with a hashability test (`test_chunk_frozen_and_hashable` in `tests/test_models.py`, which also asserts reassignment raises `ValidationError`).
- `extra="forbid"` on every model (`BBox`, `Chunk`, `Page`, `EvidenceElement`, `Document`) — pin with a `test_document_extra_forbidden` / `test_bbox_extra_forbidden`-style test asserting `pytest.raises(ValidationError, match="extra")` (`tests/test_models.py`).
- Field constraints, not validators, for single-field rules: `min_length=1` for non-empty text (`models.py:63`), `ge=1` for 1-indexed pages (`models.py:65,83,99`), `ge=0` for counts, `pattern=r"^[0-9a-f]{64}$"` for SHA digests (`models.py:118`).
- Closed vocabularies use `Literal`, not bare `str` (da24920 / WR-05 fix): `Page.status: Literal["ok", "empty", "failed"]` (`models.py:84`), `EvidenceElement.kind: Literal["text", "table", "chart", "image"]` (`models.py:100-102`), `Document.status: Literal["pending", "indexed", "failed"]` (`models.py:121-123`). Pin with `test_literal_status_validation` (`tests/test_models.py`). New status/kind fields must use `Literal`.
- Cross-model validators use `@model_validator(mode="after")`: `BBox.validate_coordinates` rejects negative/inverted boxes (`models.py:47-51`, pinned by `test_bbox_invalid_coordinates`), `Document.validate_doc_id` requires the `doc_` prefix (`models.py:127-131`, pinned by `test_document_invalid_doc_id_rejected`). Add new cross-field checks as `model_validator`, never as bare asserts at call sites.
- Every field carries a `description=` — new fields must include one.
- Pages are 1-indexed everywhere (`page_num = i + 1` in `pdf_reader.py`, `ge=1` in models). Never store 0-indexed page numbers.

**Dict-compat bridge (the rule that keeps legacy callers working):**
- Producers construct the model, then hand legacy callers a plain dict: `chunk_model.model_dump()` in `pdf_reader.py`. `model_dump()` on `Chunk` is a superset — the 4 legacy keys (`content`, `filename`, `page`, `chunk_id`) keep identical values, pinned by `test_chunk_dump_matches_legacy_keys` (`tests/test_models.py`).
- Consumers accept the superset: `LocalEmbedding.build_index` and `VectorIndex` pass extra keys through as stored metadata; `Chunk.model_validate(p)` rebuilds from stored dicts (`doc_store.py`, `main.py:203`). New retrieval/indexing code must tolerate extra keys — never assert exact key sets on chunk dicts.
- SQLite round-trips go through `model_validate(dict(row))` for reads and attribute access for writes (`doc.doc_id`, `doc.sha256`, … in `doc_store.py`). `bbox` is the special case: serialised via `model_dump_json()` on write, deserialised via `BBox.model_validate_json()` on read, `None` when the column is NULL.
- JSON round-trips use `model_dump_json()` / `model_validate_json()` — pinned by `test_json_roundtrip` (`tests/test_models.py`).
- Legacy-dict adaptation pattern for tests/producers: `Chunk(doc_id=..., extraction="pypdf", **legacy_data)` (`tests/test_models.py`).

**Pure helpers in `models.py`:**
- `CONFIG_VERSION` (`models.py:14`) versions the extraction/chunking policy; cache paths embed it (`cache_dir_for` in `models.py:17-30` returns `base / sha256 / CONFIG_VERSION`). Pinned by `test_config_version_and_cache_dir_helper`. Bump `CONFIG_VERSION` when chunking policy changes; never reuse a version string for a different policy.
- `cache_dir_for` and `doc_id_for` both guard with `^[0-9a-f]{64}$` and raise `ValueError(f"Invalid sha256 digest: {…!r}")` on traversal/short/non-hex input (`models.py:28-29`, `upload_validation.py:47`). Pinned by `test_cache_dir_for_traversal_rejected` and `test_doc_id_for_invalid_sha_rejected` (`tests/test_models.py`, `tests/test_upload_validation.py`). New hash-accepting helpers must copy this guard.

## SQLite Idioms (must-follow — `doc_store.py`)

**Per-operation connections (WR-01 fixed in da24920):**
- Every public method opens its own connection via `self._connect()`, uses it inside `with self._connect() as conn:`, commits explicitly. `_connect` is a `@contextmanager` generator that configures (`timeout=5.0`, `row_factory = sqlite3.Row`, `PRAGMA journal_mode=WAL`, `PRAGMA busy_timeout=5000`), `yield`s, and always `close()`s in a `finally:` block (`doc_store.py`). There are no long-lived connections and no connection pooling — this is what makes `DocStore` safe under Streamlit's rerun-every-interaction model and is pinned by `test_two_instance_interleave_R1` (`tests/test_doc_store.py`). New `DocStore` methods must use `with self._connect() as conn:` — never hold a connection on `self`.

**Schema versioning:**
- DDL lives in `SCHEMA_V1_DDL` list, wired through `MIGRATIONS: dict[int, list[str]]`, applied by `_apply_migrations` comparing `PRAGMA user_version` (prints `[DocStore] Applied migration v{version}`). New schema changes add a `2: [...]` entry plus `PRAGMA user_version = 2` handling — never edit `SCHEMA_V1_DDL` in place for a breaking change. Pinned by `test_user_version_set` (`tests/test_doc_store.py`).

**Query shape:**
- All SQL is parameterized (`?` placeholders, never f-strings). Tables use `TEXT PRIMARY KEY` (`doc_id`, `chunk_id`) and composite `PRIMARY KEY (doc_id, page_num)` for pages.
- Upserts use `ON CONFLICT(...) DO UPDATE SET` covering all mutable columns (IN-06 fixed in da24920): document upsert refreshes `filename/size_bytes/num_pages/status/upload_time/num_chunks` (`doc_store.py`), chunk upsert refreshes `doc_id/filename/page/content/char_start/char_end/bbox_json/extraction/embedding_model` (`doc_store.py:250-...`). Pinned by `test_upsert_document_updates_size_and_time` and `test_record_chunks_full_column_update_on_conflict` (`tests/test_doc_store.py`). New upserts must refresh every mutable column, not just content.
- Ordering: `list_documents` is `ORDER BY upload_time DESC`; `get_chunks_for_doc` is `ORDER BY page ASC, rowid ASC` (`doc_store.py:296`, WR-06 fixed in da24920 — insertion order within a page, not lexical chunk-ID order). Chunk IDs are additionally zero-padded (`f"{chunk_prefix}_p{page_num}_{j:04d}"` in `pdf_reader.py:76`) so lexical order matches numeric order.
- `sha256` carries a `UNIQUE` constraint for dedup; concurrent same-file uploads surface `sqlite3.IntegrityError`, which production handles with an `st.info("already recorded")` guard (`main.py:218`) instead of crashing (WR-03 fixed in da24920).

**Type guards:**
- Public methods fail fast on wrong types before touching the DB: `isinstance(doc, Document)` / `isinstance(page, Page)` / per-element `isinstance(c, Chunk)` with `TypeError(f"Expected X instance, got {type(...).__name__}")`, `isinstance(chunks, list)`, `isinstance(doc_id, str)` / `isinstance(sha256, str)`. `record_chunks([])` returns early without opening a transaction. New `DocStore` methods must follow this guard-first shape.
- Reads return models or `None` (`get_document`, `get_by_sha` return `None` on miss); lists return `list[Document]` / `list[Chunk]`, never `None`.

**Test isolation for stores:**
- `DocStore` tests take `tmp_path` and construct a fresh `DocStore(tmp_path / "<name>.db")` per test (`tests/test_doc_store.py`). Never point tests at `data/documents.db`. Direct-SQL assertions use `store._connect()` — the only sanctioned white-box connection access outside `DocStore`.

## Upload Validation Idioms (must-follow — `upload_validation.py`)

**Fail-fast order (do not reorder):**
1. `%PDF` magic-byte prefix check → `ValueError("Not a valid PDF: missing %PDF header — {filename}.")`.
2. Size cap (`len(raw) > MAX_FILE_MB * 1024 * 1024`) → `ValueError("File too large ({mb:.1f} MB > ...)")`.
3. `pypdf.PdfReader(io.BytesIO(raw))` probe → page count → zero-page rejection (`num_pages < 1` → `ValueError("PDF contains no pages — {filename}.")`, da24920 / WR-03) → cap (`num_pages > MAX_PAGES`) → `ValueError("Too many pages (...)")`; probe exceptions chain via `raise ValueError(f"Unreadable PDF ({err}) — {filename}.") from err`.
4. Hash + `doc_id` derivation only after all checks pass.
- New validation steps slot into this order (cheap syntactic checks before expensive parsing, hashing last). All `ValueError` messages end with `— {filename}` so the UI can display them verbatim via `st.error(str(e))` (`main.py`). Pinned by `test_corrupt_invalid_rejected_WR07`, `test_oversize_rejected`, `test_over_page_rejected`, `test_zero_page_pdf_rejected` (`tests/test_upload_validation.py`).
- Constants `MAX_FILE_MB` / `MAX_PAGES` are module-level; `main.py` imports `MAX_FILE_MB` for the pre-buffer size pre-check (`main.py:29,126-132`, WR-04 fixed in da24920 — `uploaded_file.size` is checked before `getvalue()`).

**Hashing identity:**
- `sha256_bytes` hashes in 1 MiB slices (`upload_validation.py`); `doc_id_for(sha)` validates `^[0-9a-f]{64}$` then returns `f"doc_{sha[:16]}"` (`upload_validation.py:47`). `ValidatedUpload` is `@dataclass(frozen=True)` with `doc_id/filename/sha256/size_bytes/num_pages`. Rename-stability (`same bytes + different filename → same sha/doc_id`) is pinned by `test_rename_yields_same_doc_id` (`tests/test_upload_validation.py`).
- Chunk IDs derive from the content hash, not the filename: `f"{sha12}_p{page_num}_{j:04d}"` with filename fallback when no hash is supplied (`pdf_reader.py:76`, `main.py`). Zero-padding (`:04d`) is load-bearing for lexical ordering (WR-06 fix). Pinned by `test_hash_chunk_ids_stable_across_rename` (`tests/test_pdf_reader.py`).

## Error Handling

**Guard-clause validation (primary pattern — `vector_index.py`):**
- Fail fast with `TypeError` for wrong types and `ValueError` for bad values, before mutating state:
  ```python
  # `vector_index.py`, `doc_store.py`
  if not isinstance(vector, list) or not all(isinstance(x, (int, float)) for x in vector):
      raise TypeError("Vector must be a list of numbers.")
  if k <= 0:
      raise ValueError("k must be a positive integer.")
  ```
- Full guard inventory to mirror: metric whitelist, missing embedding fn, non-dict document / missing `content` key / non-string content, dimension lock-in and mismatch, bad query type, vector-length checks in every distance helper.
- Empty-store behaviour: `search()` returns `[]` instead of raising when nothing is indexed.
- Tests assert every guard with `pytest.raises(<Type>, match="<message fragment>")` — see `test_add_vector_guards` (`tests/test_vector_index.py`) and `test_vector_index_initialization`. New guards must add a matching `pytest.raises` case with the exact message fragment.

**Pydantic validation errors:**
- Model misuse surfaces as `pydantic.ValidationError`, not `TypeError`/`ValueError`. Tests assert it directly: `with pytest.raises(ValidationError): chunk.content = "Mutated text"`, `match="extra"` for forbidden extras, bare `pytest.raises(ValidationError)` for bad SHA patterns, `match="Invalid BBox coordinates"` for inverted boxes, `match="doc_id must start with 'doc_'"` for bad IDs, bare `pytest.raises(ValidationError)` for bad `Literal` statuses (`tests/test_models.py`). New model constraints need a matching `ValidationError` test.

**Hash-guard errors:**
- `doc_id_for` / `cache_dir_for` misuse surfaces as `ValueError(match="Invalid sha256")` (`tests/test_models.py`, `tests/test_upload_validation.py`). New digest-accepting helpers must raise the same shape.

**Optional-dependency pattern (`local_llm.py`):**
```python
try:
    from groq import Groq
except ImportError:
    Groq = None
# ... later, in AiModel.__init__:
if not Groq:
    raise ImportError("groq package is missing. Please run `pip install groq`.")
```
- Use this shape for any new optional third-party import: `try/except ImportError → None` at top, explicit `ImportError` with install hint at use site.

**Config-failure pattern:**
- Missing `GROQ_API_KEY` raises `ValueError` with remediation text naming both secret locations. New required-config checks must raise with the same "what + where to set it" message shape. Covered by `test_ai_model_missing_key_raises` (`tests/test_local_llm.py`), which deletes the env var via `monkeypatch.delenv("GROQ_API_KEY", raising=False)`.

**UI-level handling (`main.py`):**
- Size pre-check before buffering: `uploaded_file.size > MAX_FILE_MB * 1024 * 1024` → `st.error(...)` + `continue` (`main.py:126-132`). Never call `getvalue()` before this gate for new large-file paths.
- Per-file `try/except ValueError` around `validate_pdf_bytes`, reporting via `st.error(str(e))` then `continue` so one bad PDF never aborts the batch. `PdfReader` construction + `extract_text` + `get_paragraphs` + `get_page_records` sit inside a second per-file `try/except Exception → st.error("Could not extract text …") + continue` (CR-02 fixed in da24920, `main.py:186`). New per-document processing must use this isolate-and-continue shape, never a bare `except:`.
- Dedup-hit persistence (CR-01/CR-03 fixed in da24920): on `existing_doc` with `st.session_state.local_embedding is None`, restore via `doc_store.get_chunks_for_doc(doc_id)` → `LocalEmbedding().build_index([c.model_dump() ...])` (`main.py:162`); on fresh ingest, persist via `doc_store.record_chunks([Chunk.model_validate(p) for p in paragraphs])` before `upsert_document` (`main.py:203`), with `except sqlite3.IntegrityError → st.info("already recorded")` for the check-then-insert race (WR-03 fix, `main.py:218`).

**Page-level fault isolation (`pdf_reader.py`, WR-02 fixed in da24920):**
- The per-page `try/except` now encloses extraction + cleanup + `split_text` + `Chunk(...)` construction; whitespace-only splits are skipped (`if not content: continue`), pages with zero surviving chunks record `Page(status="empty")`, failures record `Page(status="failed", error=str(err))` and `continue`. Pinned by `test_page_failure_isolated` (`tests/test_pdf_reader.py`, monkeypatches `extract_text` to fail on page 2 only).

**Script-level handling (`scripts/benchmark_baseline.py`):**
- Fail fast with a message + `sys.exit(1)` when a prerequisite is missing (corpus PDF absent). Wrap new script entry points in `if __name__ == "__main__":` calling a single `run_*()` function, mirroring `run_benchmark()`.

**Defensive indexing:**
- `paragraphs[-1]["page"] if paragraphs else 0` guards empty PDFs; `if chat_history:` / `if last_user_msgs:` guards history contextualisation; zero-magnitude vectors return `0.0`/`1.0` instead of dividing by zero. Preserve these guards when touching the same code. Zero-magnitude behaviour is pinned by `test_zero_magnitude_vector` (`tests/test_vector_index.py`).

## Logging

**Framework:** `print()` to stdout/stderr only. No `logging` module, no log levels, no structured logging.

**Patterns:**
- Lifecycle prints with module prefix: `print(f"[LocalEmbedding] Loading ...")`, `print("[LocalEmbedding] Model ready.")`, `print(f"Successfully extracted text from {self.filename}...")` (`pdf_reader.py`), `print(f"[UploadValidation] Validated {filename} ({doc_id}, {num_pages} pages, {size_bytes} bytes)")` (`upload_validation.py`), `print(f"[DocStore] Applied migration v{version} to {self.db_path.name}")` (`doc_store.py`).
- Benchmark progress prints use numbered-stage headers (`[1/4]`, `[2/4]`, …) plus `[Memory]` / `[Output]` tags. New long-running scripts must use the same staged-print shape.
- Corpus generator prints per-file byte sizes at completion.
- User-facing feedback goes through Streamlit, never `print`: `st.error` / `st.info` / `st.success` / `st.status` / `st.write` / `st.warning` / `st.progress` (`main.py`). Rule: `print()` for developer diagnostics, `st.*` for anything the user should see. Filenames in UI strings are wrapped in backticks (IN-03 fix, `main.py:130,186,260`).
- Tests assert behaviour, never log output — no `caplog`/`capsys` usage in the suite.

## Function Design

**Size:**
- Small single-purpose methods (5–25 lines). Largest functions are UI layout blocks in `main.py` (sidebar upload loop, chat handler) — these are sequential Streamlit layouts, not logic to extract, unless adding genuinely new UI sections.
- Test functions are single-behavior (5–35 lines each); one `test_*` per behavior, not one mega-test per class. The tracer test (`test_tracer_chunk_to_store_roundtrip`, `tests/test_models.py`) is the sanctioned exception — it spans Reader → Chunk → DocStore deliberately as a contract slice. The restore test (`test_restore_chunks_to_embedding_from_doc_store`, `tests/test_doc_store.py`) is the second sanctioned cross-layer test — DocStore → `model_dump` → `LocalEmbedding` rebuild.

**Parameters:**
- Keyword-friendly with sane defaults: `prompt: str = "tell me what is this pdf about", local_embedding=None, chat_history=None` (`local_llm.py`); `k: int = 3` (`local_embedding.py`, `vector_index.py`); `model_name: str = "all-MiniLM-L6-v2", distance_metric: str = "cosine"`. New retrieval parameters must default so existing call sites keep working.
- `PdfReader.__init__(self, file_or_path, filename=None)` accepts a path string, bytes stream, or file object (`pdf_reader.py`); `extract_text(doc_id=None, sha12=None)` falls back to filename-derived identity — callers must pass the validated `doc_id`/`sha12` (`main.py`).
- `VectorIndex.search(query: Any, ...)` accepts a string or a precomputed vector; `LocalEmbedding.build_index(chunks: list)` accepts `list[str]` or `list[dict]`. Extend with the same accept-both-types + normalise-early shape.
- `DocStore.__init__(self, db_path: str | Path)` accepts both path types, resolves, and creates parent dirs (`doc_store.py`).
- Fixtures take `monkeypatch` / `tmp_path` and return the handle for assertions: `mock_groq_client(monkeypatch) -> mock_client`, `mock_sentence_transformer(monkeypatch) -> mock_model` (`tests/conftest.py`). Request fixtures by name as test args (`def test_ai_model_prompt_assembly(fake_env_groq_key, mock_groq_client):` in `tests/test_local_llm.py`).

**Return values:**
- Data methods return plain containers or models: `list[dict]` chunks with `content`/`filename`/`page`/`chunk_id` keys (`pdf_reader.py`), `list[tuple[dict, float]]` of `(document, distance)` sorted ascending (`vector_index.py`), joined context string (`local_embedding.py`), `Document | None` on store misses (`doc_store.py`), `list[Document]` / `list[Chunk]` on listings (`doc_store.py`), `ValidatedUpload` from `validate_pdf_bytes` (`upload_validation.py`).
- Generation is a token generator (`yield chunk.choices[0].delta.content` in `local_llm.py`) consumed by `st.write_stream`, which returns the full string (`main.py`). New LLM entry points must yield strings (not return a completed string) to preserve streaming. Pinned by `test_ai_model_streaming_yield` (`tests/test_local_llm.py`).
- No `None`-on-error: failures raise, empty results return `[]`/`None`-on-miss (`vector_index.py`, `local_embedding.py`, `doc_store.py`).
- Corpus builders return `None` and write to disk; `generate_all_corpus_files() -> dict[str, Path]` maps names to paths.

## Module Design

**Exports:**
- Single public class per module, imported by name — no `__all__`, no factories, no re-exports. Wire new cross-module dependencies the same way (`from x import Y` at top level, e.g. `main.py`).
- `models.py` exports models + `CONFIG_VERSION` + `cache_dir_for`; `upload_validation.py` exports `validate_pdf_bytes` + `sha256_bytes` + `doc_id_for` + `ValidatedUpload` + caps; `doc_store.py` exports `DocStore` + `SCHEMA_V1_DDL` + `MIGRATIONS`.
- Benchmark script exposes `run_benchmark()` + `get_current_rss_mb()` and runs only under `if __name__ == "__main__":`. Corpus module exposes `generate_all_corpus_files()` under the same guard. Importing these modules must never trigger work.

**Barrel files:**
- None and not wanted: the flat layout means a new module is just a new root-level file plus an import where used. New test files are new `tests/test_*.py` files (auto-discovered via `python_files = ["test_*.py"]` in `pyproject.toml`).

## Test Conventions (must-follow)

**Fixtures — use `tests/conftest.py`, do not re-mock inline:**
- `fake_env_groq_key` — sets `GROQ_API_KEY` via `monkeypatch.setenv` to an obviously inert value (`tests/conftest.py`). Use in every `AiModel` construction test.
- `mock_groq_client` — patches the exact symbol `AiModel` calls (`local_llm.Groq` via `monkeypatch.setattr(local_llm, "Groq", lambda api_key=None: mock_client)`) and yields 5 canned tokens `["This ", "is ", "a ", "grounded ", "answer."]` through `choices[0].delta.content` (`tests/conftest.py`). Assert via `mock_client.chat.completions.create.call_args[1]` (`messages`, `model`, `stream`).
- `mock_sentence_transformer` — patches the exact symbol `LocalEmbedding` calls (`local_embedding.SentenceTransformer`), returns deterministic 384-dim L2-normalised `float32` vectors keyed off text length (`tests/conftest.py`). Assert `store._vector_dim == 384` after `build_index`. The restore test takes this fixture so the rebuild stays offline.
- `sample_pdf_path` — resolves `tests/data/corpus/clean_digital.pdf` (`tests/conftest.py`). New PDF tests should prefer the fixture over a local `CORPUS_DIR` constant (older upload-validation tests still duplicate it — do not copy that).
- `tmp_path` (pytest builtin) — every `DocStore` test builds an isolated DB under `tmp_path` (`tests/test_doc_store.py`); the tracer test uses `tmp_path / "tracer.db"`. Never write test DBs to the repo tree.
- Tests never hit network, GPU, or disk-external resources: Groq is mocked, `SentenceTransformer` is mocked, corpus PDFs are generated locally by `generate_corpus.py` and read from disk. The only unmocked heavy path is `scripts/benchmark_baseline.py`, which intentionally loads the real model (not a test).

**Mocking rules:**
- Mock at the seam the production code calls (module attribute), not the library root: `local_llm.Groq`, not `groq.Groq`; `local_embedding.SentenceTransformer`, not `sentence_transformers.SentenceTransformer`. Use `monkeypatch.setattr` (auto-reverted), never manual patch/unpatch. The page-cap/zero-page tests patch `pypdf.PdfReader` globally — prefer patching the `pypdf` reference inside `upload_validation` if tests ever parallelise (residual IN-05, `01-REVIEW.md`).
- `MagicMock` for injected collaborators: `mock_embedding = MagicMock(); mock_embedding.get_context.return_value = "..."`. Assert collaboration with `assert_called_once()` and inspect `call_args`.
- Page-failure injection: monkeypatch the page object's `extract_text` to raise on one page only, then assert the remaining pages still extract and record (`tests/test_pdf_reader.py`) — the model for all future fault-isolation tests.
- What NOT to mock: `VectorIndex` math (pure stdlib — test directly with hand-computed vectors); `RecursiveCharacterTextSplitter` behaviour (assert observable chunk size/metadata); corpus PDFs on disk (read the real generated files); `hashlib.sha256` (compare `sha256_bytes` against it directly, `tests/test_upload_validation.py`); `DocStore` storage engine (use a real SQLite file under `tmp_path`, never a mocked store).
- Known coupling (accepted): `tests/test_vector_index.py` binds to private API (`_cosine_distance`, `_euclidean_distance`, `_distance_metric`, `_vector_dim`) — white-box by design for the math-guard suite. `tests/test_doc_store.py` uses `store._connect()` for direct-SQL assertions — the only sanctioned white-box DB access. Do not extend private-API coupling to other modules.

**Assertion idioms:**
- Float math: `assert pytest.approx(actual, abs=1e-5) == expected`.
- Errors: `with pytest.raises(<ExcType>, match="<message fragment>"):` — `TypeError`/`ValueError` for guards, `ValidationError` for models (`match="extra"`, `match="Invalid BBox coordinates"`, `match="doc_id must start with 'doc_'"`), `ValueError(match="Invalid sha256")` for digest guards, `sqlite3.IntegrityError` for the SHA-unique constraint, `ValueError match="Not a valid PDF: missing %PDF header"` / `match="File too large"` / `match="Too many pages"` / `match="contains no pages"` for upload validation.
- Model equality: `assert retrieved == doc` / `assert retrieved_chunks[0] == chunk` (Pydantic `__eq__`, `tests/test_models.py`, `tests/test_doc_store.py`).
- Corpus preconditions: `assert pdf_path.exists(), "Corpus file ... must exist"` before reading — failure message tells the runner to run the generator first.
- Streaming: `tokens = list(generator)` then compare exact token list and joined string.
- Keep test imports minimal — there is no `tests/*` ruff `F401`/`F841` exemption, so unused imports fail CI.

**Corpus generation rules:**
- `tests/data/corpus/generate_corpus.py` is deterministic, offline, fixed filenames — use `reportlab` only (stdlib + reportlab, no network). Scanned-sample generator must use only vector rects (no `drawString`) so the zero-text property the scanned test depends on is structural. Corrupt fixture must be raw invalid bytes, not a valid PDF. Regenerate via `python tests/data/corpus/generate_corpus.py` (CI runs this before pytest).

## Streamlit Idioms (must-follow)

- `st.set_page_config(...)` is the very first Streamlit call (`main.py`) — never insert a Streamlit call above it.
- Initialise all `st.session_state` keys via the key/default loop; add new keys there, never lazily mid-layout. Phase 1 added `doc_ids: set` alongside `indexed_files`, `document_metadata`, `local_embedding`, `chat_history`.
- Heavy singletons go behind `@st.cache_resource`; per-`load_dotenv()`-before-read ordering inside the cached function matters because `AiModel.__init__` reads the env.
- Upload-loop staged pattern (`main.py`): `with st.status("Processing documents…", expanded=True)` wrapper → size pre-check via `uploaded_file.size` before `getvalue()` (WR-04) → `# 1.` single `getvalue()` read → `# 2.` `validate_pdf_bytes` with `st.write("Validating …")` → dedup check via `get_by_sha` with `st.info` skip + CR-01 session-index restore when `local_embedding is None` → guarded extraction block (`PdfReader` construction + `extract_text` + `get_paragraphs` + `get_page_records` inside `try/except Exception`, CR-02) with `st.progress(0.0)` updated per page and `st.warning` per failed page → `build_index` → `record_chunks([Chunk.model_validate(p) ...])` + `upsert_document` inside `try/except sqlite3.IntegrityError` (CR-03 + WR-03) → best-effort `.cache/` write guarded by `try/except OSError` → session-state update + `st.success`. New upload steps slot into this order.
- Render pattern: `with st.sidebar:` layout, `st.status` for staged work with `.update(label=..., state="complete", expanded=False)` on completion, `st.chat_message` + `st.markdown` for history replay, `st.chat_input(..., disabled=(...))` for gated input, `response_stream → st.write_stream(response_stream) → append to history`.
- State mutation ends with `st.rerun()` after batch updates.
- Identity in session state is hash-based: `doc_ids: set[str]` (`doc_<sha16>`) is the dedup key, `document_metadata[filename]` carries `doc_id/upload_time/pages/chunks` display fields. Timestamps are canonical UTC ISO (`datetime.now(timezone.utc).isoformat()`, WR-08 fix) stored in state/DB, formatted to `meta["upload_time"][:19].replace("T", " ")` only at render time (`main.py:258`).
- Missing-key test validity depends on no `secrets.toml` in the test env (`st.secrets[…]` raising `FileNotFoundError`) — never commit a secrets file that would silently change this path.

## Config Patterns (must-follow)

- `load_dotenv()` is called inside the cached loader, and `AiModel` reads `st.secrets["GROQ_API_KEY"]` first with `except (KeyError, FileNotFoundError)` fallback to `os.environ.get("GROQ_API_KEY")`. New secrets must follow this exact precedence: `st.secrets` → `.env`/`environ` → raise `ValueError` naming both locations.
- Pytest config lives in `pyproject.toml:13-20`: `testpaths = ["tests"]`, `python_files = ["test_*.py"]`, `python_functions = ["test_*"]`, `filterwarnings` ignoring `UserWarning`/`DeprecationWarning`.
- Runtime deps are pinned in `requirements.txt` (includes `numpy>=1.26.0,<3.0.0` range + `pydantic==2.11.9` exact). Test-only deps live in `requirements-test.txt` (`pytest`, `reportlab`, `ruff`, `psutil`, all minimum-version `>=` pins) and are installed via `pip install -r requirements-test.txt` in CI (`.github/workflows/ci.yml:28`) — never add test-only packages to `requirements.txt`.
- Never commit secrets: `.env` is gitignored (`.gitignore:1`); existence only is noted, contents are never read or quoted. The `fake_env_groq_key` value is an obviously inert mock string (`tests/conftest.py`).
- `data/` is gitignored — the production `data/documents.db` never commits. `.cache/` is gitignored (WR-07 fixed in da24920, `.gitignore` last line) — cache dumps never commit.
