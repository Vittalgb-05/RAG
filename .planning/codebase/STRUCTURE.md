## Directory Purposes

**Repo root (`./`):**
- Purpose: Entire application — flat layout, no packages or submodules; all Python source modules live at top level and import each other by bare module name.
- Contains: 5 Python source files, `requirements.txt`, `pyproject.toml`, `README.md`, `CLAUDE.md`, plus support directories.
- Key files: `main.py`, `local_llm.py`, `local_embedding.py`, `vector_index.py`, `pdf_reader.py`, `requirements.txt`, `pyproject.toml`

**`tests/` (new in Phase 0):**
- Purpose: Offline correctness proof — one test module per domain module plus shared fixtures; runs with zero network, zero GPU, zero API key via mock seams.
- Contains: `__init__.py`, `conftest.py`, `test_vector_index.py`, `test_pdf_reader.py`, `test_local_embedding.py`, `test_local_llm.py`, `data/corpus/`.
- Key files: `tests/conftest.py` (all mock seams), `tests/test_local_llm.py` (prompt/streaming contracts), `tests/test_pdf_reader.py` (corpus-backed ingestion)

**`tests/data/corpus/`:**
- Purpose: Deterministic document fixtures covering the PDF shape matrix; generated on demand, never hand-authored binaries as source of truth.
- Contains: `generate_corpus.py` (the only committed source file) + 6 generated PDFs (working-tree artifacts, regenerated by CI before every test run).
- Key files: `tests/data/corpus/generate_corpus.py` (`generate_all_corpus_files() -> dict[str, Path]`), `tests/data/corpus/clean_digital.pdf` (primary 20-page fixture used by tests + benchmark)

**`scripts/`:**
- Purpose: One-off operational harnesses, not imported by the app or tests.
- Contains: Single `benchmark_baseline.py` — the Phase 0 performance profiler.
- Key files: `scripts/benchmark_baseline.py` (`run_benchmark()`, `get_current_rss_mb()`)

**`.github/workflows/`:**
- Purpose: CI enforcement — lint + corpus regeneration + full test suite on every push/PR to `main`.
- Contains: Single `ci.yml` (4-step `test` job on `ubuntu-latest` + Python 3.11).
- Key files: `.github/workflows/ci.yml`

**`application_screenshots/`:**
- Purpose: Static documentation assets embedded in `README.md` only; never loaded by application code.
- Contains: `image.png` (active chat), `image_2.png` (upload screen), `mermaid_diagram.png` (pipeline diagram asset).
- Key files: `application_screenshots/image.png`, `application_screenshots/image_2.png`

**`.devcontainer/`:**
- Purpose: Reproducible dev environment for VS Code / GitHub Codespaces.
- Contains: Single `devcontainer.json` — base image `mcr.microsoft.com/devcontainers/python:1-3.11-bookworm`, Python + Pylance extensions, pip-install hook, Streamlit auto-start on port 8501.

## Naming Conventions

**Files:**
- Flat `snake_case` module names mapping 1:1 to the single class inside: `local_llm.py` → `AiModel`, `local_embedding.py` → `LocalEmbedding`, `vector_index.py` → `VectorIndex`, `pdf_reader.py` → `PdfReader`. Entry point is the bare `main.py` (Streamlit convention).
- Test files mirror the module under test: `test_<module>.py` (`test_vector_index.py` → `vector_index.py`), per `pyproject.toml:15` (`python_files = ["test_*.py"]`).
- Operational scripts use `snake_case` verb-noun form: `benchmark_baseline.py`, `generate_corpus.py`.

**Directories:**
- `lowercase` with underscores where needed (`application_screenshots`, `.devcontainer`, `.planning`, `tests`, `scripts`, `data`, `corpus`, `workflows`). No Python packages beyond `tests/__init__.py` — `scripts/` has no `__init__.py` (run as `__main__`, imports via `sys.path` insert in `benchmark_baseline.py:16-17`).

**Classes / Functions / Variables:**
- Classes use `PascalCase` (`AiModel`, `LocalEmbedding`, `VectorIndex`, `PdfReader`); test-local doubles use `Mock`-prefixed `PascalCase` (`MockDelta`, `MockChoice`, `MockChunk` in `tests/conftest.py:27-37`).
- Functions and methods use `snake_case` with verb-first names (`extract_text`, `get_paragraphs`, `build_index`, `get_embeddings`, `ask_a_question_from_pdf_stream`, `save_uploaded_pdf`, `load_ai_model`, `add_vector`, `add_document`, `run_benchmark`, `get_current_rss_mb`, `generate_all_corpus_files`, `generate_clean_digital_pdf`).
- Private helpers use single-leading-underscore (`_embed_one`, `_embedding_fn`, `_cosine_distance`, `_euclidean_distance`, `_dot_product`, `_magnitude`, `_vector_dim`, `_distance_metric`).
- Session-state keys use `snake_case` (`indexed_files`, `document_metadata`, `local_embedding`, `chat_history`); chunk-dict keys likewise (`content`, `filename`, `page`, `chunk_id`); pytest fixtures likewise (`fake_env_groq_key`, `mock_groq_client`, `mock_sentence_transformer`, `sample_pdf_path`).

## Where to Add New Code

**New Feature (e.g. new ingestion source, new query mode):**
- Primary code: Add the domain logic to the matching existing module (`pdf_reader.py` for parsing, `local_embedding.py`/`vector_index.py` for retrieval, `local_llm.py` for generation), then wire the UI trigger + rendering in `main.py` (sidebar block or chat-loop block).
- Tests: Add to the mirroring test module (`tests/test_<module>.py`); add shared doubles/fixtures to `tests/conftest.py`, never inline in a test file. If the feature needs a new document shape, extend `tests/data/corpus/generate_corpus.py` with a new generator + register it in `generate_all_corpus_files()` rather than committing a binary.

**New Component/Module (e.g. reranker, persistent store, eval script):**
- Implementation: Create a new top-level `snake_case` module (e.g. `reranker.py`) exposing one class, mirroring the existing one-file-one-class pattern; import by bare name (`from reranker import Reranker`) as done in `main.py:21-23` and `local_llm.py:3-4`.
- Tests: Create `tests/test_reranker.py` following the `test_vector_index.py` header-comment + plain-function pattern; reuse `mock_sentence_transformer` / `mock_groq_client` from `conftest.py` instead of inventing new seams.
- Benchmark: Extend `scripts/benchmark_baseline.py` with a new numbered stage block (copy the `[N/4]` print + `perf_counter` + dict-report shape) rather than creating a second script.

**Utilities:**
- Shared helpers: No `utils/` directory exists — small UI helpers live inline in `main.py` (e.g. `save_uploaded_pdf` at `main.py:70-81`, `load_ai_model` at `main.py:59-67`); small domain helpers live as private methods on the owning class (e.g. `LocalEmbedding._embed_one` at `local_embedding.py:28-33`); benchmark helpers live as module functions (`get_current_rss_mb` at `scripts/benchmark_baseline.py:23-25`); corpus helpers live as `generate_*_pdf` functions in `generate_corpus.py`.

**Configuration / Dependencies:**
- Runtime deps: Append a pinned entry in `requirements.txt`.
- Test/CI-only deps (`pytest`, `reportlab`, `ruff`, `psutil`, `numpy`): Installed inline in `.github/workflows/ci.yml:28` — do NOT add to `requirements.txt` (keeps the Streamlit Cloud deploy image lean).
- Lint/test behaviour: Edit `pyproject.toml` (`[tool.ruff]` for lint, `[tool.pytest.ini_options]` for discovery).
- Secrets: Local key in untracked `.env` (`GROQ_API_KEY=...`); cloud key in Streamlit secrets — both consumed by `local_llm.py:23-27`, no code change needed for new env vars beyond reading them there.

**Import facts:**
- `main.py:21-23` imports all three domain classes (`AiModel`, `LocalEmbedding`, `PdfReader`) but never imports `VectorIndex` directly — it reaches the store only through `LocalEmbedding.store` (`local_embedding.py:26`).
- `local_llm.py:3-4` imports `PdfReader` and `LocalEmbedding` for its headless fallback (`local_llm.py:41-45`); it never imports `VectorIndex` or `streamlit`-UI helpers.
- `local_embedding.py:7-8` imports `SentenceTransformer` + `VectorIndex`; direction is one-way, no cycles.
- `pdf_reader.py:1-5` and `vector_index.py:11-12` import only third-party/stdlib packages — they are the dependency leaves.
- `groq` is an optional import guarded by `try/except` with `Groq = None` fallback and an explicit `ImportError` in `AiModel.__init__` (`local_llm.py:6-9, 20-21`).
- `tests/conftest.py:6-10` imports `os`, `pathlib`, `unittest.mock`, `numpy`, `pytest` only; per-test modules import exactly one source module each (except `test_local_llm.py`, which also imports `unittest.mock.MagicMock` for the inline embedding double).
- `scripts/benchmark_baseline.py:15-17` bootstraps `sys.path` with `REPO_ROOT` so the script runs from any cwd; it imports `pdf_reader`/`vector_index` at top level but `sentence_transformers` + `numpy` lazily inside `run_benchmark()` (`benchmark_baseline.py:66,97`) so stages 1–2 work even without torch installed.
- `tests/data/corpus/generate_corpus.py:6-19` imports `reportlab` only — zero project imports, so corpus generation never depends on app code being healthy.
